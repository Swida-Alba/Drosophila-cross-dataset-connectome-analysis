Comparison — Cross-Dataset Morphology tab

Compare the morphology of the queried neurons across datasets: enter query types, select two or more datasets, and get pairwise vector_v2 similarity matrices per dataset pair, a seeded null baseline for context, and 3D overlay scenes with every dataset bridged into one reference template. The same run also writes each selected volume's intra comparison under intra_dataset/<DATASET>/ — one folder holds both halves, the same contract as Connectivity ▸ Comparison. The intra controls (Method, Aggregation Level, caps, cache) stay visible and apply to that intra half.

Dataset scope. Only FAFB, male-cns and BANC participate — these are the datasets with a bridging transform inside the 2-hop accuracy guard (FAFB↔male-cns, FAFB↔BANC, male-cns↔BANC are 1–2 transforms; everything else, e.g. hemibrain or MANC, needs 7–9 and is refused with a banner). BANC comparisons carry a standing reliability warning: public BANC skeleton products mix L2 / full / µm sources. First BANC use bootstraps its morphology population artifacts from the locally cached skeletons (one-time, offline).

Quick start

  1. Select two or more datasets (the list shows every dataset; pairs without a bridging transform are refused at run time with the red banner).
  2. Enter the Neurons to Compare — types or patterns (e.g. APDN3, aMe.*). With Auto Type Mapping on (the default), types are resolved through the shared validity-aware resolver — curated renames (e.g. APDN3 → SLP249) and valid splits resolve across datasets, and conflicted types fail closed; a type missing in one dataset shows up as an explicit empty row in the report. Turn the mapping off to fall back to raw same-name/pattern resolution.
  3. Optionally pick a Reference Template for the overlay scenes (defaults to the first selected dataset).
  4. Click Run Comparison (the same button as the intra-dataset mode — two or more selected datasets switch it to this mode). The resulting folder holds intra_dataset/, cross_dataset/ and a hub report.html.

Cross-dataset options

  • Auto Type Mapping (on): validity-aware cross-dataset type resolution, as described above.
  • Null Sample Size (default 200, range 10–1000): how many seeded random target neurons per query feed the null baseline.
  • 3D Overlay Scenes (on): render the bridged overlay scenes.
  • Fetch Missing Skeletons Online (on): fetch skeletons that are not in the local cache.
  • Custom Groups (LabelMapper): the always-visible grouping card doubles as the cross run's tier-0 label overlay (a loaded preset or inline board). It also feeds the query's first resolution lane: a token naming one of the preset's labels pools that label's members from each dataset's own column, so the same label pairs across the datasets being compared, and it claims the token before the auto type mapper — a label that is also a native type name resolves as the group, and the pooled set is the group's neurons rather than the whole mapped type's population. With a preset the type-level comparison is the label × label matrix (morph_labeltype_matrix.csv) and the inter-dataset comparison is the same-label diagonal (overview.csv, morph_matched_label.csv); the native type matrix stays a diagnostic. Labels are identities and are never re-resolved through the auto type mapper — see the label-mapper guide.

How scoring works

  • For each ordered dataset pair A → B, the queried neurons' members of A are transformed into B's render space and scored against the members of B with the production vector_v2 scorer (block-weighted whitened cosine — the same scorer Find Similar uses). NBLAST is not used cross-dataset.
  • Raw cross-dataset scores have a high, query-dependent baseline. Every pair therefore reports a null baseline: the p95/median of the same queries scored against ~200 seeded random target neurons. The sample is shared across queries and runs, so repeat runs are fast. Member pairs above the baseline p95 are flagged in morph_bodyid_scores.csv, and the raw per-neuron scores are exported as the morph_bodyid_matrix.csv bodyId × bodyId matrix. vector_v2 is a whitened cosine that can be negative, so the report renders it on a diverging blue–white–red scale.
  • Scores are comparable within a dataset pair (one frame), not across pairs — the report states each pair's frame (frame disclosure). In particular, A→B and B→A are not symmetric: each direction transforms into a different render space and uses a different whitening basis, so the numeric scores and baselines differ. The overview table discloses this.
  • Per type and dataset, at most Max Members per Type neurons (default 25) enter the scoring; the 3D scenes render at most Scene Members per Type (default 3) per dataset for legibility.
  • With a LabelMapper preset loaded, the run also writes the label-aligned type view: the SAME member pairs folded by standard label instead of native type name. Native type names are dataset-scoped homonyms that can carry one, several, or no labels — the native matrix stays beside it as the ground truth, and parameters.json discloses the exact axes semantics.

Inter-dataset = matched label only. With a LabelMapper preset the type-level comparison carries the preset labels; the overview and morph_matched_label.csv report only the same label across the source and target (the label matrix diagonal), matching the Connectivity Comparison tab's cross overview. The native type × type matrix remains on disk as a diagnostic CSV; cross-label cells are not part of the inter-dataset comparison.
Comparison, not discovery. With two or more datasets this mode compares the neurons you queried. To search a whole dataset morphologically, use the Find Similar sub-tab (intra-dataset); for cross-dataset homolog discovery, use the Connectivity tab's Find Homolog search with its optional morph qualification.
