Dataset and connection cache

In Dataset Cache, choose a dataset and set the batch size and parallel worker count. Pull Dataset Metadata downloads/verifies only the neuron table, ROI table, and the materialized neuron index (datasets/<dataset>/ + neuron_indexes/<dataset>/neuron_index.parquet); no connections are fetched, and already-present files are never re-downloaded. Pull Complete Connections fetches the full resumable connection cache (cache/<dataset>/connections.parquet), skipping neurons that are already cached (rows or verified zero-outdegree). Download All Skeletons sits below the dataset pull controls, right above its own progress bar, together with the Cache Simplification selector that chooses the percent of skeleton nodes removed when writing those cache files (0 = raw by default — the cache stores raw skeletons and simplification is applied at visualization time; higher values store pre-simplified trees), and a Skeleton Batch Size input (64 default). Progress is reported per completed skeleton, so the batch size does not affect progress granularity; larger batches only reduce the repeated per-batch metadata queries. The Parallel workers field above sets how many skeleton fetches run concurrently - raising it is the main speed lever (up to what the server tolerates). The connection pull uses the batched builder and shared cache/<dataset>/connections.parquet cache, so it can resume an interrupted pull. Enable Force rebuild only when the existing connection cache needs to be replaced.

Storage

The Storage card (below Dataset Cache) inspects and reclaims disk space. Nothing is removed automatically — the card scans on first open (and via Scan Now), and every removal previews the exact paths and bytes before you confirm. Actions are disabled while a dataset or skeleton pull is running.

Scan coverage: the scanner always covers the default output directory, the remembered per-tab output folders, every folder recorded under Recorded output roots, and the folders seen in the run history. A root is recorded automatically the first time a run exports to a non-default directory; type one more folder and press Remember to record it manually, and click the ✕ on a chip to stop scanning it (nothing is deleted by forgetting).

Every row shows a hover tooltip with the full path (cache rows list the exact files that a clear would remove), and the folder_open button at the end of each row opens that folder in the system file manager.

Caches lists one row per cache class and dataset with its size, last-used time, and rebuild cost. Deleting the NB match cache goes through the finder's own clearer; the incoming-connections row removes the parquet and its completion-state file together (the state file can never be deleted alone, and is never left behind). Protected data — availability snapshots, the coverage snapshot, per-dataset available_rois.json, and cache/user_mappings/ (your LabelMapper presets) — is never offered. BANC and FAFB connection caches rebuild offline from the local tables; NeuPrint ones refetch from the server. A clear takes full effect after an app restart (in-process caches may still serve cleared data until then). When Cache Only (Offline) is enabled and the selection contains connection data, a warning is shown — the clear still runs.

Exported data lists timestamped run folders under the default output directory (plus any folder typed into the extra-scan field). Registered NeuronBridge tools show a source-data vs deliverables split: Prune Source Data runs the Compact prune regardless of the runs' original output mode (deliverables stay, each folder's cleanup_audit.json records the removals). Delete Folder removes whole run folders after a checkbox double-confirm. Folders belonging to an active run are locked. Removals of cache files and deleted folders are appended to cache/storage_audit.json.

App settings

The Input Auto-Suggestion toggle controls the type-ahead suggestions in every neuron query box (the analysis tabs, the mapping and layer panels) and in the Advanced Layer Editor's neuron cells: dataset type / instance / bodyId names while typing, plus a Recent/Frequent query history when the field is empty. A pick adds its chip and then keeps that query's rows on screen, and the history marks them the same way: a name already in the input stays listed, tinted and ticked — so several entries can be handled from one list without retyping and the rows never shift under the pointer. Clicking a ticked row takes that chip back out, exactly like the chip's own x; on a history row the small × beside it is the other action, which drops the entry from the history and keeps the chip. Any click that closes the list (or ESC, or leaving the field) resets it to the history. ArrowDown moves into the open list and ArrowUp leaves it from the first row; Enter adds the highlighted entry — or removes it, when that row is ticked — and moves the highlight to the next one, so a run of picks works without the mouse. Disabling the toggle restores plain chip inputs. The change is saved immediately and applies to every input.

Default Settings

Tool-tab selections remain one-time: changing a control inside a tab applies only to that run. The Default Settings card defines the values every tab starts with. Adjust the controls, click Save Defaults, and the overrides are stored in ui/local_config.json (under user_defaults) so they survive restarts. Reset clears every override and restores the built-in values. Saved values are validated; an invalid entry in the config file falls back to the built-in default.

Dataset preparation

Use the converter's directory contract exactly NeuPrint tables are fetched automatically. FAFB is prepared from raw Codex downloads placed in datasets/<dataset>/downloads/; BANC metadata and connections are prepared from its public release products. Do not rename raw files or place them directly in the dataset root. The UI reports ✓ local only after both the generated neuron table and merged connection table exist.

NeuPrint

  1. Get a NeuPrint token from neuprint.janelia.org/account.
  2. Enter it above, click Save Tokens, then click Test NeuPrint.
  3. The selected dataset is fetched and cached automatically on first use.

FlyWire FAFB v783

Create datasets/flywire_FAFB_v783/downloads/ from the project root and keep the original compressed filenames from the Codex FAFB download.

Required raw inputs for local connection analysis:

  • classification.csv.gz
  • connections_princeton_no_threshold.csv.gz (preferred), or connections_princeton.csv.gz / connections.csv.gz as fallbacks

Recommended metadata enrichment: names.csv.gz, coordinates.csv.gz, neurons.csv.gz, cell_stats.csv.gz, and consolidated_cell_types.csv.gz. The converter can proceed without these, but labels and metadata will be incomplete.

Optional visualization inputs: fafb_v783_princeton_synapse_table.csv.gz (local synapses) and sk_lod1_783_healed.zip (local skeletons).

python src/FAFB_file_converter.py

Or select flywire_FAFB_v783 in a tool and run it; the tool invokes the same local preparation automatically. Verify that the root contains flywire_FAFB_v783_allneurons_neuron_df.parquet and flywire_FAFB_v783_merged_connections.parquet, then click Refresh.

BANC v888 / v626

Choose exactly one identifier and do not mix versions. DROCAT prepares the metadata and connection tables automatically from the public BANC release bucket; no FlyWire/Codex login or CAVE token is needed. The legacy files below are an optional offline fallback for users who already have a manual bundle:

  • neurons.csv.gz
  • connections_princeton.csv.gz

Do not manually create or rename a *_allneurons_neuron_df.csv file; that is generated output. If the public bucket is unavailable, convert the legacy v626 bundle with:

python src/BANC_file_converter.py

For v888, run the converter with the selected dataset name:

python -c "import sys; sys.path.insert(0, 'src'); from BANC_file_converter import ensure_banc_data; d='banc_v888'; ensure_banc_data(d, 'datasets/' + d)"

Verify that the selected root contains both <dataset>_allneurons_neuron_df.parquet and <dataset>_merged_connections.parquet, then click Refresh. BANC skeletons are fetched on demand from the public release bucket and cached as raw .swc.zst; no CAVE token is involved. Use the converted local files for pathfinding, networks, and tabular analysis.

CAVE token scope A CAVE token is needed only for workflows that explicitly fetch FAFB data or skeletons through CAVE. It does not replace the local input files, and a token alone does not prepare a FAFB dataset.
