3D Skeleton (plot3dSkeleton)

The 3D Skeleton tab renders neuron morphology, synapses and brain region meshes from any configured dataset into an interactive HTML scene. It runs VisualizeSkeleton.plot_neurons() in the background. For pathway graphs see the separate Network guide.

Quick start

  1. In the Layer Structure tree, three layer rows are ready by default — add neurons to them, or click Add Layer for more rows.
  2. Pick the dataset; keep Brain Mesh = native (each dataset draws its own template outline; for BANC scenes this is the brain portion of the whole-CNS outline). ROI meshes are optional and start unselected.
  3. Click Generate 3D Skeleton.

Inputs & examples - the layer tree

The tree mirrors the script's nested-list layer model: each row is one layer and may hold several neurons (type, instance, bodyId or regex). Drag a row to reorder layers; drag a neuron chip onto another row to regroup it. Optional layer names feed the legend (unnamed layers are auto-named): the per-row name input is collapsed behind the small edit button so the rows stay compact.

Neuron valueMeaning

The Match by mode (exact / starts with / contains / ends with / regex) converts every neuron in the tree into a regex pattern, and the Search Columns selector (auto / type / instance / bodyId) scopes name resolution — the same neuron-search backend as Find All Paths. Upload formats for neuron lists are documented in Input File Formats.

Layer editor modes

Three segmented buttons on one row (Standard, Advanced, File upload) pick how the neuron layers and their colors are defined, and a Synapse Mode box plus Synapse Threshold sit directly below them. Only Standard mode uses the on-screen Neuron Colors / Synapse Colors palette editors; the other two modes take neuron/synapse colors from the in-file settings. The Brain Region ROIs panel (including ROI Colors) is independent of the layer editor — the editor defines neurons and synapses, never ROI meshes — and is identical in every mode.

  • Standard — the classic drag-and-drop layer rows (add neurons to a row, drag rows to reorder, drag chips between rows). An Export CSV button writes the current order to the layer-map CSV format (layer,neuron). The Neuron Colors / Synapse Colors palette editors are shown here.
  • Advanced — selecting it shows the editable layer editor table directly (it is not collapsed). Each row's Layer cell is a selection box that starts at 1 for a new table and only offers the currently available layers (so layer 2 is never offered unless layer 1 is in use). Existing 0-based CSVs remain supported, but every used layer number must be continuous. The colour columns follow the synapse mode: Synapse color for synapse, or Pre-synaptic + Post-synaptic colors for pre-post sites (and the exported/uploaded CSV matches that same column set). The single-color picker (alpha + Bokeh palette) is opened from a color cell's picker button or the palette button beside each colour input in the Add Row form. Empty color cells display (auto). The See available neurons viewer appends one row per selected entry and assigns the whole viewer-selection batch to the next layer; the Add Row neuron field also provides dataset-aware suggestions and, with an empty field, your Recent queries. Picking an entry adds the chip and keeps that query's rows on screen — in either list, a name you already added stays listed, tinted and ticked — so several neurons go into one cell without retyping and the rows never shift under the pointer. Clicking a ticked row takes that chip back out, the same as the chip's own x; the small × beside a Recent entry — shown only while that row is hovered, so it never competes with the tick — is a different action, which drops it from your query history and keeps the chip. A click on the field, an Escape or leaving the cell closes the list and resets it to Recent. Rows are auto-saved to disk as you edit; use Export CSV to download, or Upload CSV to load a file into the table. The Neuron Colors / Synapse Colors palette editors are hidden (colors come from the file); the Brain Region ROIs panel stays available.
  • File upload — upload a custom-layer CSV directly. Its color columns are used as-is (no editable table; the Neuron Colors / Synapse Colors palette editors are hidden, ROI Colors stay available).

The same custom-layer CSV can also be produced/edited by hand. It has a layer column (numbers may start at 0 or 1; the lowest value is treated as the first layer) and a neuron column (any legal query name, the legacy id_type_instance name also works). Optional color columns:

Hemisphere analysis

The Hemisphere selector (next to Search Columns) restricts the plotted neurons to one side:

  • both (default): all neurons.
  • left: only left-hemisphere neurons.
  • right: only right-hemisphere neurons.

Hemisphere assignment is automatic per neuron: the Soma side / hemisphere column wins when present, otherwise the instance suffix (_R → right, _L → left). Neurons with neither are unclassified (U) and are always included in every option — so datasets whose neurons lack hemisphere notation (e.g. some non-NeuPrint tables) are never silently dropped.

Manual suffix search still works — a chip like aMe12_R or .*_R selects one side per type; the Hemisphere selector applies the same rule to every neuron automatically, including those without a suffix.

Options

The render controls live in a General Appearance card with three expansions — Neuron Skeleton Appearance, Synapse Appearance and Brain Region ROIs (independent) — beside the Export Video / GIF, Individual Profiles (PDF / PPTX) and Advanced Settings cards; the re-export band sits below them all. The four blocks below mirror those expansions.

General Appearance

  • Skeleton Mode: tube (detailed) or line (fast). In line mode every neuron shows a soma marker: the sphere sits at the SWC label==1 node, and skeletons without that marker (about a third of male-cns) get the node nearest the NeuPrint somaLocation annotation marked automatically — or the fattest radius node when no annotation exists — before line simplification; never on BANC, whose skeletons carry no soma signal. Spheres below 0.55% of the scene's longest axis are grown to that floor at save time, so the soma stays a visible dot at whole-CNS overview; line soma sizes are display choices, not measurements.
  • Normalized Tube Radius (BANC datasets only): scale BANC tube radii to a normalized diameter; Radius Target (nm) (default 240, range 10–1000) sets the target diameter.
  • Neuron Legend Mode: layer, type, tree, or single. ROI meshes always keep independent legend entries and rank after every neuron entry (brain mesh, then VNC mesh, last).
  • Expandable legend (tree): the exported interactive HTML replaces the flat legend with a collapsible panel at the original legend position (top-right). Without custom layer names the hierarchy is type → bodyId/instance; with custom layer names or a layer-map CSV it is group → type → bodyId/instance. Each expandable row shows a color swatch and a count of unique neuron items. A singleton custom bodyId group is rendered as one direct row with count 1, so a skeleton plus its soma mesh does not become two neurons or a redundant child leaf. Toggling a type hides its skeleton and pre/post site traces, individual neurons toggle separately, and synapse/mesh rows sit below the types (meshes last). Pre/post site traces also appear as their own pre sites / post sites leaves under their type (or group), and any item list longer than 10 rows expands into a mini scrollable area. Static exports keep the plain type-level legend. Cross-dataset transformed query overlays use the source neuron's native type label in their bodyId row rather than a mapped flywireType value (for example, MCNS SMP227 remains SMP227). The panel also shows the double-click interval: a second click on the same row under 300 ms isolates that row; repeat the double-click to bring back the rows the page opened with — which excludes a template half the run embedded hidden. The eye in the panel header is the other control: it shows or hides every row, that embedded half included.
  • Freeze 3D view when toggling the legend (checkbox in Advanced → Export, on by default): Plotly re-autoranges the three scene axes over the visible traces on every redraw, so hiding a legend row or a tree-panel eye moved the framing instead of just the drawn traces. When checked, the exported viewer HTML (and its _simplified.html copy) pins its axes on first render to the extents of every trace — hidden layers included, each axis padded by 1/32 of its span, which is Plotly's own 3D margin — so a toggle only changes what is drawn. It also freezes the box's x:y:z proportions at the ratio those extents imply, because Plotly's aspectmode='data' otherwise re-derives them from the visible traces and one hidden mesh reshapes the anatomy. A 🔒/⛶ Freeze/Fit button in the page's top-left corner (or the F key) switches the autoscaling back on, and the ⌖ Recenter button just below it (or the C key) moves the rotation pivot onto the traces you can currently see — a frozen box keeps its pivot at the centre of the whole scene, so after hiding the VNC outline the brain would otherwise orbit around the empty space it left. Recentering moves only the pivot; the box and its proportions stay pinned. It does nothing in fit mode, where the pivot already follows the visible traces — and pressing Fit clears that pivot, because the offset is normalized against the pinned box and fit mode shrinks the box onto what you can see, so a leftover number would leave the anatomy hanging off the rotation centre. Freezing again restores the pivot you chose, unless you panned in the meantime. A page that opens with a context half embedded but hidden runs this control itself at setup, so its orbit starts on the anatomy you can see rather than on the middle of the gap between the two halves — measured on a male-cns brain-only page, a 40° turn slid the brain 212 px across the frame before and 2 px after. Nothing else about the framing moves: the box, its proportions and the zoom are exactly what they were. All three floating controls — the two view buttons and the light/dark switch in the other corner — carry a hover hint on one row that names the key and states the current state ("View is frozen: legend toggles keep the framing (F to fit)"; the switch says which theme the click selects), drawn by the page's own stylesheet rather than a native tooltip, which costs a second to appear. The freeze also re-applies itself after the page's single reset camera button and a double-click, which restore a layout snapshot taken before the freeze existed and would otherwise hand the scaling back to the visible traces. Plotly's second reset button is removed from the toolbar: the two differ only by which snapshot they restore, and the kept one returns the page to the framing it opened with. The pin is injected page script that exits early under navigator.webdriver, so view PNGs, individual profiles and video frames still autoscale exactly as before. A brain or VNC envelope the run did not ask to show is still inside the pinned box, because the page has one box and a half you can reveal has to be in it — so a brain-only male-cns page opens framed to the whole CNS, 1.46× wider along its longest axis than the brain alone needs, and its VNC eye then draws the nerve cord without moving the framing at all. The hidden half costs the orbit nothing, though: the page opens pivoted on the half it draws, so turning the scene keeps the brain where it is instead of swinging it around the cord's empty space. Nothing about a frozen view changes once you have it; Fit (F) is the control that follows content. The frame you open on is unchanged either way; untick the box to hand scaling back to Plotly.
  • Background: white or black. The default neuron palette follows it — Category10 on white, Set3 on black — until you pick a palette manually.
  • Theme switch in the exported HTML: the main viewer HTML (and its _simplified.html copy) carries a floating 🌙/☀️ button (top-right, or press T) that flips the page between light and dark for viewing — background, legend and dropdown/hint text all follow. It always opens with the configured Background; static exports (view PNGs, per-neuron files, video) keep the fixed background, and neuron/synapse colors stay as generated.
  • Brain Mesh: native (dataset's own template), BANC (explicit BANC whole-CNS outline), FAFB, male-cns, or none — those five and nothing else; the pre-rename template/whole names are retired. VNC Mesh toggle for male-cns/manc/BANC. Both pick what the page opens showing: on male-cns and BANC the half you leave off is still written into the exported HTML — hidden, and at reduced detail — so whoever opens the page can reveal it from the legend tree without re-running anything. Other datasets have a single native template (FAFB the brain, hemibrain the half-brain outline), so nothing extra is embedded. Neither hidden half is added to the downloadable mesh model. Brain Mesh Color and VNC Mesh Color each default to Auto — the fixed adaptive outline #74A8D6 at 4% opacity on any background; uncheck either to pick a fixed outline color and opacity for that half alone. The two halves sit as one row each, columns aligned, so a trio cannot be read as belonging to the wrong side — the left cell names the half, and for the cord that cell is the VNC Mesh checkbox (the brain's is the Brain Mesh menu above). Each applies to the embedded hidden half as well, so a nerve cord the viewer reveals arrives in the colour set for it, not the default blue.

Neuron Colors

  • Neuron Opacity: global fallback opacity for skeletons (0=invisible, 1=solid).
  • Full bokeh palette catalog with custom editing. Preset palettes are picked from a full-width name dropdown; every option in the dropdown list shows the palette name with a strip preview filling the row to its right (discrete palettes as distinct color blocks, continuous palettes as a smooth gradient), so palettes are visible before selection. The selected palette shows in the interactive preview row, where swatches can be dragged to reorder discrete palettes, a live range slider selects part of the palette, and reset restores the original order and full range.
  • Custom colors: starts empty — no preset palette is shown until colors are added. Use the shared Pick color popup, free-form color formats, or individual swatches of any Bokeh palette (choose the palette in the dropdown, click a swatch to select it, then press Add color). The popup's alpha slider uses 0.05 steps and only embeds alpha when Override alpha is checked; otherwise the renderer's global Neuron Opacity is inherited. Added colors appear in the horizontal preview bar, where they can be dragged to reorder or removed with their red cross.
  • Default follows the background (Category10 / Set3) until a palette is picked manually.

Synapse Colors

  • Synapse Mode: an outlined dropdown — synapse (paired markers between consecutive layers), pre-post sites (the input/output sites of the queried neurons), or skip (hide markers; the BANC default — the first pre/post render there triggers a one-time ~3.9 GB synapse download, warned in-app). The cutoff Synapse Threshold sits beside it.
  • Synapse Shape (synapse mode): cone / scatter / sphere / tetrahedron.
  • Pre/post shape (pre-post sites mode): solid (post/input sites as spheres, pre/output as cones) or scatter (post/input as circles, pre/output as diamonds).
  • Synapse Threshold (formerly Min Synapse Count): minimum synapse weight for a marker to be shown; in pre-post site mode only sites whose connection with a neighbour meets this threshold are shown. It sits to the right of the Synapse Mode box, below the layer-editor buttons.
  • Synapse Size (an integer 1–12, a fold of the real pre→post distance: 1 = the real distance; scatter mode defaults to 1 and mesh renders to 3× real). In pre/post-site mode every site is uniform and uses the full mean real connector distance as its glyph size because each sphere/cone is centered on its own pre- or post-synaptic site; a one-layer view estimates it from sampled upstream/downstream pairs. Uniform Synapse Size applies to paired markers, and Opacity remains global.
  • pre-post (Pre/post-synaptic site mode): instead of the paired synapses between adjacent layers, this renders the pre- and post-synaptic sites of every queried neuron. Post-synaptic (input) sites draw as spheres, pre-synaptic (output) sites as cones (or circle/diamond scatter markers, see Pre/post shape), both colored by the neuron's layer and given separate pre <layer> / post <layer> legends. It is not a paired-synapse view: the partner is not restricted to the adjacent layer. An orange in-page banner and a note in user_warning_notes.txt flag its behavior.

Brain region ROIs

  • The Mesh ROIs suggestions start with the complete dataset primary-ROI list from datasets/<dataset>/*metadata*. Type all to request every locally available ROI.
  • Include L/R variants keeps explicit (L)/(R) entries in the primary list; otherwise bilateral pairs are shown once.
  • Include sub-primary ROIs appends non-primary entries to the primary list.
  • No ROI mesh is selected by default.
  • Mesh ROIs: presets or regex (ME.*, all, primary).
  • ROI Colors: Auto gray, or any palette assigned in its exact displayed order; custom and discrete-palette reordering is preserved.
  • Each resolved ROI mesh, including bilateral expansions, is a separate trace and legend entry.
  • ROI Mesh Opacity.

Advanced

Export Video / GIF and Individual Profiles (PDF / PPTX) are their own collapsible cards above Advanced Settings; the Advanced Settings expansion holds:

  • Cache Neurons/Synapses: faster repeat renders.
  • Show Figure: open the interactive page in the browser after the render (on by default in this tab).
  • Simplification Method (NeuPrint tube mode): fast is the default direct path with render-time mesh simplification. fine is the FAFB-style transform rebuilt from the shared raw .swc.zst cache; fine meshes are not persisted. artistic uses vertex-cluster mesh decimation. All methods use batched parallel online skeleton fetching across layers. The selector is available for NeuPrint and FAFB/BANC tube renders; line mode bypasses it.
  • Mesh Simplification: defaults to 90% faces removed for fast and 95% for fine/artistic in this tab, including FAFB/FlyWire; line mode does not apply mesh simplification. Use Default Mesh Simplification reverts a custom value to those defaults.
  • Export Method: webdriver (fast, needs Chrome 109+) or kaleido (stable fallback). Export Scale and Export Views.

The two cards above Advanced Settings:

  • Individual Profiles (PDF / PPTX): the Export Individual Profiles checkbox (off by default) gates the export, which writes one profile per group — with Summary Format (pdf / pptx) and Images Per Page (cols/rows) (3/2) setting the document layout, plus camera views. Profile Granularity decides how far the legend tree is walked to form one profile group: Per legend entry (legend, the default and the historical behaviour) follows the Neuron Legend Mode; Per layer (layer), Per neuron type (type) and Per bodyId (body) group by that tree level whatever the legend mode is, because they read the identity every trace carries (body gives one profile per neuron leaf, so it can be many files). Companion soma meshes and pre/post sites always follow their owner's profile.
  • Export Video / GIF: fps, degrees per frame, rotation axis, GIF scale.

Re-export from a stored page

The card at the bottom of the page re-renders the outputs of a page that is already on disk — no dataset query, no skeleton cache, no original script. It sits in a band of its own below the render controls, with the Skeleton Re-export Output panel beside it. It reads the figure back out of the page's own Plotly.newPlot(...) payload and, when the run wrote one, takes its cameras and background from visualization_manifest.json. Pick a page from Stored 3D Skeleton Page (the viewer HTML of every plot-3d_* run folder under the configured output directories and your recent runs, newest first; the degraded _simplified.html copies are never offered), set the knobs below, and press Re-export from Page. It runs as an ordinary background job, so the progress steps, log and file list behave like a normal render; internally that job is the plot3d_reexport tool, whose two re-exporters are documented in the 3D Skeleton guide.

ControlEffect
Re-export ProfilesOne PNG per profile group into <page stem>_reexport/individual_profiles/. Capped at 300 renders per run (groups × views): the groups that fit render first and the log names the skipped ones.
Re-export GranularityThe same levels as Profile Granularity above (legend / layer / type / body). A page can only be split as finely as its own legend identity allows — a page rendered in layer legend mode has no finer types to separate.
Re-export ViewsCamera views rendered for each profile group.
Re-export VideoAdds a full turn: frames in <stem>_reexport/pics_<fps>fps_<plane>/, then forward and backward MP4s (plus GIFs). Frames already on disk are reused when the settings match.
Video FPS / Degrees / Frame / Rotate / Also GIF / GIF Scale Frame rate, rotation step per frame (2° = 180 frames per turn), horizontal vs vertical orbit, GIF conversion and GIF downscale.
Frame Methodwebdriver (default) loads the page once in one Chrome session and only moves the camera per frame — also the only engine that handles a scene too large for kaleido; kaleido renders frame by frame. If no browser can be started it warns and falls back to kaleido on its own.
Frame ScaleResolution multiplier for the profile PNGs and the video frames.
Frame Auto-cropTrims the background off profiles, and applies one consistent crop across all video frames so the video does not jitter.

With a manifest, the video's horizontal orbit inherits the run's own handedness (a MANC scene turns the other way), and the profile cameras are the ones the run used. A page from before visualization_manifest.json still re-exports — its profiles are grouped from the identity stamped on its own traces — but its cameras then come from the built-in default view set, and the orbit keeps the historical handedness.

Nothing in the source run is touched. Every re-exported file is written next to the chosen page in its own <page stem>_reexport/ folder, so re-running the same settings with the same knobs reuses the frames already rendered instead of recomputing them.

Output

One timestamped folder per run, named after the dataset abbreviation and the layer names:

                                          readable colors; only the active
                                          synapse color family is populated
    visualization_manifest.json         - what the scene means (dataset, view
                                          cameras, legend mode, freeze state,
                                          per-trace roles), so the page can be
                                          re-exported later without its source
    parameters.txt                      - exact parameters of the run
    user_warning_notes.txt              - notes/warnings of the run

With Export Views on, PNG screenshots ({name}_{view}.png in exported_views/) are written into the run folder; the rotating Export Video adds videos/GIFs plus their pics_<fps>fps_<plane>/ frames, and Individual Profiles adds individual_profiles/ plus its PDF/PPTX summary. In pre-post site mode the merged synapse export (and the in-page banner, plus the user_warning_notes.txt entry) describes the per-site rows rather than paired inter-layer synapses. A re-export never writes here: its results go into a sibling <page stem>_reexport/ folder.

3D export needs Chrome when Export Method = webdriver and Export Views is on; use kaleido if Chrome is unavailable.
Exported run guide: every successful run also writes _UserGuide_please_read_me.html into the run folder — a self-contained explanation of every output file, every table column, and any warnings recorded for the run. Format (html / txt / markdown / disabled) is set in Settings → Default Settings → Run Guide Format.
