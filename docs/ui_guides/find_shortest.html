Shortest Paths

Find only the shortest (minimum hop-count) paths between source and target neuron groups. For every reachable pair, all tied shortest paths are kept. Discovery starts from target neurons and follows incoming branches to enrolled source bodyIds. Runs on the full pathfinding pipeline (discovery, enrichment, outputs, visualization) with shortest-only enumeration.

Per-pair minimum: the minimum is enforced per exact (source bodyId, target bodyId) pair, before any type aggregation — not a single global path-length cutoff. A type-level row can therefore mix pairs of different hop counts: each pair contributes its own shortest paths.

Quick start

  1. Add Source Neurons (e.g. aMe12, aMe10).
  2. Add Target Neurons (e.g. PPL101, DN1p).
  3. Click Shortest Paths.
Use a small source set: if Source Neurons contains more than one type/name query, the page warns that each query can expand to many source bodyIds and enlarge the target-rooted search. Prefer one source type or query. Use explicit bodyIds with bodyId output enabled when exact source-target pairs are needed.

All-neurons queries (all_neurons)

Typing the special chip all_neurons as the source or target loads the full (typed) neuron set on that side, so the run fetches every adjacent neuron at the given thresholds (Min Synapse Count):

  • all_neurons replaces every other chip in the same input.
  • Source and target cannot both be all_neurons.
  • An all_neurons side forces Max Intermediate Layers = 0 (direct connections only). With shortest-path semantics this reports every direct edge (one hop) from or to the other side at the given thresholds.
Script/API parity: the backend (FindNeuronConnection.InitializeNeuronInfo) enforces the same rules, so passing sourceNeurons=['all_neurons'] in code behaves identically. All typed neurons are loaded from local data (works offline with Cache Only).

Depth cap (default: 5 intermediate layers)

  • Max Intermediate Layers = 0 means direct connections only. For a positive value M, paths are capped at M + 1 hops.
  • The tab default is 5 (deeper than the Complete Paths default of 2), because shortest-path searches typically target deeper routes. Increase it further when a query needs deeper intermediate layers. Backward discovery continues until the enrolled source bodyIds are reached or this bound is hit.
  • If the bound truncates an active frontier, results are shortest only within the explored, threshold-filtered graph. A path at that boundary is a constrained solution, not proof of a globally shortest route.

Score formulas

Every connection and path is scored on the thresholded graph D_t (edges with weight ≥ Min Synapse Count). Ratios use the global total incoming weight so the denominator reflects the whole dataset, not just the query:

ScoreFormulaRange
connection_ratiow_ij / Σ_k w_kj over D_t (edge weight ÷ total input to the post neuron)0–1
traversal_probabilitymin(1.0, connection_ratio / 0.3) (30% input = maximal)0–1
block_probability1 − traversal_probability0–1
path_probΠ of the edge traversal probabilities over the path0–1
min_weightweakest edge synapse count along the path (the bottleneck)integer
min_ratiosmallest edge connection ratio along the path0–1

At the type level the aggregate probabilities are computed from the deduplicated bodyId-level pairs of D_t: type-level traversal probability uses the product method by default (1 − Π(1 − p_pair)), which models parallel channels. Full derivations live in Score Calculation Guide.

No algorithm selector: the tab enumerates through FastGraph.find_paths_shortest_strongest_first — a per-target reverse BFS outlines the min-hop DAG, a maximin bottleneck DP annotates every branch with the best achievable strength, and tied shortest paths are emitted best-first in strength order with a k-way merge across targets — polynomial in graph size per pair. (The find_paths_shortest_backward exporter also exists in FastGraph, but the pipeline does not call it.) The branching^depth explosion of Complete Paths does not exist here, but the total number of min-hop paths can still grow quickly at depth (tied routes multiply at every layer).
Path budget (Max Paths, BodyId): the min-hop enumeration runs through the StrongestFirst budget — paths are emitted strongest-first (descending bottleneck) and, when the budget (max_paths_bodyid, 0 = auto → 1,000,000) is reached, all ties at the achieved cutoff tau are drained and weaker paths dropped: the output is exactly "all min-hop paths with bottleneck ≥ tau". Unbitten runs are identical to the complete min-hop set.
The Edge Budget is off in shortest mode. Its purpose (bounding the exponential path count) does not apply to shortest enumeration, and flooring (a threshold raise) preserves pair reachability but not shortest distance — a dropped weak edge can silently inflate a reported distance. The tab has no Edge Budget input at all and always sends 0; API callers passing graph_edge_limit_bodyid still get the full un-floored graph here because the setting is ignored. The Max Paths (BodyId) input is the knob that bounds this mode.
Memory sizing (Discovery Batch Budget). Discovery memory for many broad targets otherwise grows with targets × union frontier × depth — a measured 2026-10-02 run (242 circadian targets at depth 5, ~450 GB RSS) is why batching is the default: labels stream to shortest_discovery_store/ and enumeration holds at most one batch of targets (bounded by the state budget). The Path Budget bounds only the result (emitted paths) and the Edge Budget never applies here — neither controls discovery memory. Deep runs with a single broad target remain depth-bound: lower Max Intermediate Layers or raise Min Synapse Count. Results are identical with or without batching (the run folder's shortest_discovery_diagnostics.batching records the realized composition).

Applied threshold & bottleneck provenance

The exported parameters distinguish the requested Min Synapse Count from the cutoff that describes the materialized output. In every run, applied_threshold is the canonical equivalent threshold; applied_threshold_source identifies whether it came from the request or a budget. The related values are:

ValueMeaning
requested_thresholdThe Min Synapse Count entered by the user.
applied_threshold / tau_canonicalThe minimal threshold that reproduces the output. When the StrongestFirst budget bites, this is w2 + 1; in an unbitten run it is the requested threshold.
strongest_first_budget and strongest_first_budget_bittenThe effective Max Paths (BodyId) budget and whether it was reached.
tau / strongest_first_tauThe StrongestFirst landing/collapse bound; it is the weakest retained bottleneck at the budget boundary, not always the minimal applied threshold.
w2 / strongest_dropped_bottleneckThe strongest path bottleneck omitted by the budget. The interval [w2 + 1, tau] yields the same path set.
W* / strongest_retained_bottleneckThe widest-path ceiling after lossless pruning.
edge_budget, w0, w1Shortest mode never applies this graph budget: edge_budget is reported as not applied and edge_weight_floor/edge_budget_landing remain empty. These values are active only in Complete Paths.
paths_completeWhether all shortest paths within the explored graph/depth bound were emitted; false means the StrongestFirst path budget bounded the output.

The same provenance block is written to parameters.txt, all_attributes.json, and data_details/parameters.csv, and is shown in the exported _UserGuide_please_read_me files.

BodyId enrollment

When type-level output is used, several exact bodyId pairs can collapse to one type sequence. The run records this caveat in user_warning_notes.txt. Check the root-level source_neurons.csv (isInPath) and target_neurons.csv (Checked, Layer). Skip BodyId ships on; run Shortest Paths with Skip BodyId off for specific bodyId pairs, or use Complete Paths to enumerate all paths under a chosen depth.

Advanced options

  • Keywords to Exclude from Paths — same semantics as Complete Paths. These, with Filter By, live in the Advanced Settings expansion, together with Use Cache (reuse cached connection data, on by default) and Cache Only (Offline).
  • Custom source/target names and Save Folder Name live in the Output Options card.
  • Custom Grouping — map neurons into custom groups before the comparison; see the label-mapper guide.
  • Hemisphere options: separate L/R labels, hemisphere filter, keep conserved edges, symmetry analysis — see Hemisphere analysis.
  • Find Reciprocal Connections — enriches the path graph with direct connections among its nodes.

Lmax records the exact bound used for the run; L99 is simply a practical high bound. With Skip BodyId off, bodyId-level tables (data_details/connection_info_bodyId.csv and ..._allpaths_bodyId_paths.csv) are written alongside the type-level ones. The full reference is in docs/OUTPUT_FILES.md.

Exported run guide: every successful run also writes _UserGuide_please_read_me.html into the run folder — a self-contained explanation of every output file, every table column, and any warnings recorded for the run. Format (html / txt / markdown / disabled) is set in Settings → Default Settings → Run Guide Format.
Pair report (automatic): the run writes path_report.html + paths_pair_breakdown/*.csv into its folder when it completes — capped top-paths tables with bodyId coverage, top-paths tables, and interactive offline networks. Shortest is minimum-hop per bodyId pair, so a type-level pair can still span several lengths; the per-length cap applies normally (the report states this).
