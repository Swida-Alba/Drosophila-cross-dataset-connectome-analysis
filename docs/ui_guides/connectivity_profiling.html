Comparison Connectivity tab

Compare connectivity profiles of neuron types (or bodyIds / custom groups) using identical metrics — Jaccard, weighted Jaccard, cosine, raw rank correlation and rank-correlation union (same metric set as the sibling Find Homolog sub-tab) — within one dataset or across several datasets at once.

Quick start

  1. Enter 2+ neurons (e.g. aMe12, aMe10, aMe9).
  2. Pick one or more datasets (one dataset with multiple thresholds is also supported; two or more datasets enable the cross-dataset mode).
  3. Click Run Comparison; open report.html in the output folder for the overall summary of all heatmaps.

Multi-dataset (cross-dataset) mode

Selecting two or more datasets profiles the SAME query in every dataset and compares it on two levels:

  • Intra-dataset — N×N similarity of the queried types/bodyIds/ groups within each dataset (per-dataset folder).
  • Inter-dataset — datasets × datasets similarity of the SAME queried neuron across datasets, using the homolog-finding backend algorithm (2-hop expanded partner types).

Different names of the same neuron across datasets are handled automatically via the male-cns v1.0 neuron info (the type mapper), e.g. FAFB MTe07 is standardized to MeVPLo2. cross_dataset/mapping_summary.csv lists the resolved name of every queried neuron per dataset and adds a numeric same name flag (1 when every dataset has the same non-empty name, otherwise 0).

Similarity metric formulas

Let A and B be two connectivity profiles (a dict of partner type → weight, restricted to top-K partners per direction), and let ρ denote the Spearman rank correlation of two weight vectors. The metrics are the same set used by the Find Homolog sub-tab; rank correlations are raw (−1 to 1) and there is no normalized 0–1 variant and no combined score. The overall matrix averages upstream and downstream connectivity.

MetricFormulaRange
jaccard|A ∩ B| / |A ∪ B| (partner-type sets)0–1
weighted_jaccardΣ min(w_a, w_b) / Σ max(w_a, w_b) over the union (Ruzicka)0–1
cosine(A·B) / (‖A‖·‖B‖) over the union (missing = 0)0–1
rank_corrρ = Spearman on shared partners (raw, NaN if < 3 shared)−1 to 1
rank_unionρ over the union of both partner sets (missing = 0)−1 to 1

Diagonal (self) entries are 1.0 for every metric. Rank metrics return NaN for pairs with fewer than 3 comparable partners; those cells are rendered as 0 in the heatmaps while the CSV matrices keep the original values. In multi-dataset mode the cross-dataset matrices use the homolog-finding algorithm (2-hop expanded partner types) and rank correlation values are reported raw (−1 to 1).

Advanced options

  • BodyId-Level Computation: auto (skip over 1000 bodyIds), skip, or compute always.
  • Generate Heatmaps: hierarchical (Ward) reordering of matrices, written as editable VisPath heatmaps plus Plotly heatmaps in the report.
  • Show Figures: open heatmaps in the browser.
  • Pre-build Full Dataset Cache: OFF by default - leave it off; the tool uses connections already cached. Turning it on fetches every uncached neuron and can take hours.

Output

The folder name uses the first dataset's abbreviation (MCNS = male-cns, FAFB = flywire FAFB, ...) and a sanitized query name (e.g. aMe.* → aMe):

{output_dir}/profiling_MCNS_aMe_20260815_143922/
  report.html                        # overall summary with ALL heatmaps
  parameters.json, README.txt
  intra_dataset/{dataset_folder}/    # per-dataset N×N comparisons
    results/similarity_{direction}_{metric}.csv             # type level
    results/bodyid_similarity_{metric}_{direction}.csv      # bodyId level
    results/type_avg_bodyid_similarity_{metric}_{direction}.csv
    visualization/heatmap_intra_*.html, heatmap_intra_type_avg_*.html
  cross_dataset/                     # same neuron across datasets (2+ datasets)
    mapping_summary.csv              # resolved names + same-name flag
    all_types/
      results/similarity_{direction}_{metric}.csv
      visualization/heatmap_inter_all_types_*.html
  profiles/{dataset_folder}/
    aggregated/{type}_profile.json
    individual/{bodyId}_{type}_profile.json

BodyId-level rows and axes carry the tree-legend suffixes: {bodyId}_{instance} (NeuPrint-style datasets) or {bodyId}_{type}_L/_R (FAFB/BANC), falling back to the resolved comparison type when the neuron table has no metadata — no bodyId-level export reads as a bare numeric id. Queried bodyIds in the cross-dataset matrices carry their resolved type in the row/column labels. Individual profile JSONs include the neuron's instance alongside bodyId, type, and dataset.

First run on a new dataset - profile extraction needs connection data. If the cache is empty the tool may take a long time or return insufficient profiles; run a small Find Path/Direct query first to warm the cache.
