Complete Paths

Discover multi-hop pathways between source and target neuron groups in a single dataset, e.g. aMe12 → aMe10.

Quick start

  1. Add Source Neurons (aMe12, aMe10) and Target Neurons (PPL101, PPL103) as chips, paste, or upload a list.
  2. Pick the Dataset and an Output Directory.
  3. Keep Max Intermediate Layers = 2 and click Complete Paths; watch the live log.

All-neurons queries (all_neurons)

Typing the special chip all_neurons as the source or target loads the full (typed) neuron set on that side, so the run fetches every adjacent neuron at the given thresholds (Min Synapse Count):

  • all_neurons replaces every other chip in the same input.
  • Source and target cannot both be all_neurons.
  • An all_neurons side forces Max Intermediate Layers = 0 (direct connections only) — the search stays bounded instead of exploring the whole graph. Use it to list all partners of a neuron group above a synapse threshold.
Script/API parity: the backend (FindNeuronConnection.InitializeNeuronInfo) enforces the same rules, so passing sourceNeurons=['all_neurons'] in code behaves identically. All typed neurons are loaded from local data (works offline with Cache Only).

Score formulas

Every connection and path is scored on the thresholded graph D_t (edges with weight ≥ Min Synapse Count). Ratios use the global total incoming weight so the denominator reflects the whole dataset, not just the query:

Threshold Basis: choose Synapse count (default) or Connection ratio. Ratio mode thresholds edges by the fraction of the post neuron's total input (synapses / all-post incoming), ranks paths by the exported type-path min_ratio (a realized mass share — see below), and writes data_details/ratio_synapse_map.csv with the per-neuron synapse cutoffs. Viable ratio values sit far below the synapse scale (e.g. 0.0005 on FAFB).

ScoreFormulaRange
connection_ratiow_ij / Σ_k w_kj->j — edge weight ÷ the post neuron's total incoming weight, threshold-free (min_weight = 1, all dataset sources)0–1
connection_ratio_adjedge weight ÷ the post's incoming mass counting only edges ≥ Min Synapse Count (per neuron; member-summed at type level). Always ≥ connection_ratio and moves with the threshold by design; equals connection_ratio when Min Synapse Count is 10–1
traversal_probabilitymin(1.0, connection_ratio / 0.3) (30% input = maximal)0–1
block_probability1 − traversal_probability0–1
path_probΠ of the edge traversal probabilities over the path0–1
min_weightweakest hop of the path — the realized synapse mass at that hop (the distinct bodyId edges backing it at that position)integer
min_ratiosmallest per-hop ratio — the realized share on connection-ratio runs (the hop's realized mass ÷ the post type's full-membership incoming mass; can fall below the applied bodyId-level threshold); the pair-level readout in synapse runs0–1

At the type level the two aggregate probabilities are computed from the deduplicated bodyId-level pairs of D_t: type-level traversal probability uses the product method by default (1 − Π(1 − p_pair)), which models parallel channels and makes a multi-pair type edge stronger than any single pair. Full derivations live in Score Calculation Guide.

Advanced options

  • Custom source/target names: labels used in file and folder names (e.g. aMe_clock), plus Save Folder Name for a custom output folder instead of the auto name — both live in the Output Options card.
  • Keywords to exclude: paths containing e.g. None or unknown are removed.
  • Skip BodyId in Output: only type-level results are saved.
  • Use Cache: reuse cached connection data (on by default); Cache Only (Offline): never contacts the server; requires a pre-built cache.
  • Show Figure: open the interactive figures in the browser as they are generated.
  • Custom Grouping: map neurons into custom groups before the comparison — see the label-mapper guide.
  • Find Reciprocal Connections (a standalone Core Parameters checkbox, off by default): also enumerate the reverse-direction paths and write the find_reciprocal/ outputs.
  • Hemisphere analysis: separate L/R labels, a left/right filter, symmetry outputs, and keep only hemisphere-conserved edges. See Hemisphere analysis below.

Hemisphere analysis

Both Complete Paths and Shortest Paths can restrict or split the analysis by brain hemisphere. Hemisphere assignment is done automatically per neuron:

  1. The Soma side / hemisphere column is used when present (NeuPrint neuron tables).
  2. Otherwise the instance suffix is used: _R → right, _L → left.
  3. Neurons with neither are unclassified (U) — they are always included in every option (both / left / right), so data without hemisphere notation is never silently dropped.

Hemisphere-aware

Splits type/group aggregation into _L / _R / U labels so ipsilateral and contralateral edges can be told apart (e.g. KCg-m_L → MBON01_L vs KCg-m_R → MBON01_R). Enables Symmetry Analysis and Keep Only Hemisphere-Conserved Edges.

Hemisphere filter — only left / only right / both

Restricts the query to one hemisphere: both (default) keeps everything; left keeps left + unclassified neurons; right keeps right + unclassified neurons. At the edge level, a connection is kept only when both endpoints belong to the selected hemisphere (unclassified endpoints are always kept). This works for every dataset — unlike the manual .*_R instance search, which only finds neurons that carry a hemisphere suffix in their instance name.

Manual suffix search still works — typing aMe12_R or .*_R as a source/target pattern selects one side per type; the Hemisphere selector applies the same rule to every neuron automatically, including those without a suffix.

With Skip BodyId off, bodyId-level tables (..._allpaths_bodyId.csv) are written next to the type-level ones; with Output Format = xlsx, the tables become multi-sheet Excel workbooks. The full reference is in docs/OUTPUT_FILES.md.

Every run also writes an applied-threshold provenance block to parameters.txt, all_attributes.json and data_details/parameters.csv: requested vs applied_threshold, applied_threshold_source, the StrongestFirst landing tau (strongest_first_tau), tau_canonical, strongest_dropped_bottleneck (w2) / strongest_retained_bottleneck (W*), and the Edge-Budget fields (edge_budget, edge_budget_landing, edge_weight_floor) — so a budgeted run states the exact strength cutoff its outputs represent.

Pair report (automatic)

Every run writes a per-source-target-pair report INTO its run folder when it completes: path_report.html (Overview / Global / Pair Explorer / Data, with interactive offline networks and a per-pair Source/Target bodyId coverage columns, a per-length network tab strip; multi-selections render one union pane) plus two lossless CSVs under paths_pair_breakdown/. Every capped view in the report (top-10 paths per pair and length, 50 matrix rows) states its cap and links to the uncapped CSVs. Existing folders can (re-)generate it via scripts/PathsPairReport.py <run_folder>; see docs/OUTPUT_FILES.md §1 "Pair Report".

Common issues & tips

No paths found - raise Max Intermediate Layers, lower Min Synapse, or check that targets exist in the dataset (log shows target counts).
Slow runs - large networks (100k+ neurons) take minutes. Keep the query small first, then expand.
Repeated runs - the local cache gives 10-100x speedups; the second run with the same dataset is much faster.
Exported run guide: every successful run also writes _UserGuide_please_read_me.html into the run folder — a self-contained explanation of every output file, every table column, and any warnings recorded for the run. Format (html / txt / markdown / disabled) is set in Settings → Default Settings → Run Guide Format.
