Find Homolog Connectivity tab

Find neurons similar to a source neuron via connectivity profile similarity (formerly the Find Similar sub-tab — renamed to reflect its purpose; the backend engine is unchanged). With different Source and Target datasets this is the cross-dataset homolog search (e.g. aMe12 in male-cns → candidates in hemibrain); setting Target = Source gives the within-dataset (intra-dataset) similar-neuron search. Both run the same engine (HomologFinder).

Quick start

  1. Enter one or more Source Neurons (types or bodyIds). Each input is searched independently and receives its own output folder.
  2. Choose Source Dataset and Target Dataset (set Target = Source for a within-dataset search).
  3. Click Find Homologs (Fast Search is on by default).

Similarity metric formulas

Each pair is scored with the same metrics (all are always computed; Sort By only picks the ranking cutoff). Let A and B be two connectivity profiles (partner type → weight, top-K per direction) and ρ the Spearman rank correlation of two weight vectors. Rank correlations are raw (−1 to 1); there is no normalized 0–1 variant and no combined score.

MetricFormulaRange
jaccard|A ∩ B| / |A ∪ B| (partner-type sets)0–1
weighted_jaccardΣ min(w_a, w_b) / Σ max(w_a, w_b) over the union (Ruzicka)0–1
cosine(A·B) / (‖A‖·‖B‖) over the union (missing = 0)0–1
rank_corrρ = Spearman on shared partners (NaN if < 3 shared)−1 to 1
rank_unionρ over the union of both partner sets (missing = 0)−1 to 1
shared_type_count|A ∩ B|integer
union_type_count|A ∪ B|integer
adjacency_scoreshared-partner count used for adjacency expansioninteger

When Auto Type Mapping is on, partner type names are resolved through the shared validity-aware resolver (comparison/type_resolver.py): unique renames and bridge-derived targets, and every branch of a valid split, are standardized to canonical (male-cns v1.0) names before scoring, so equivalent types resolve across datasets. A conflicted type is excluded from automatic matching (fail closed — it is never matched by raw same-name). Unmapped types keep their raw name as the counted long-tail fallback. Rank metrics return NaN for pairs with fewer than 3 comparable partners. Each saved run writes an auto_type_mapping.json recording the mapper source/version, per-status resolution counts (basis unique_type_resolutions), and whether raw-name fallback occurred.

Options

  • Fast Search: adjacency-expansion discovery (recommended).
  • Vector Pre-filtering: cosine pre-filter for speed.
  • 2-Hop Expansion: include untyped partners via 2-hop typed partners.
  • Visualize Candidates: render the queried neuron plus the top-N matches as 3D skeletons. For cross-dataset searches, the query is transformed into the target brain and rendered inside the target scenes as the query_transformed_* overlay layer (a standalone source-dataset scene is only drawn as a fallback when the transform is unavailable). In the interactive tree legend, the query uses its source-native type label rather than a mapped flywireType value; an MCNS SMP227 query therefore stays labeled SMP227 in FAFB.
  • BodyId-level tree legend: a custom group containing one neuron is shown as one direct row with count 1. Skeleton and soma companion traces do not create a redundant child leaf or count as two neurons. Multi-neuron groups remain expandable.
  • Analysis visualizations default to Skeleton Mode = line for speed. For high-quality morphology, use Visualization → Skeleton, or select tube with the fine method and 95% simplification in the advanced visualization settings.
  • Auto Type Mapping: resolve partner type names across datasets through the shared validity-aware resolver — licensed renames and valid splits resolve; conflicts fail closed (recommended for cross-dataset searches).
  • Pre-build Full Dataset Cache: leave OFF; the search fetches what it needs.

Morph qualification (cross- or intra-dataset, optional)

Morph Qualification adds a morphological second opinion to the connectivity ranking. It runs only on the visualized top-N candidates, and needs a supported target among FAFB / male-cns / BANC — cross-dataset and same-dataset (intra) runs alike:

  • The query skeleton is transformed into the target's render space (identity for same-dataset runs; their query bodyIds are excluded from the null sample) and scored with the production vector_v2 scorer (no NBLAST cross-dataset).
  • Qualification mode:
    • Null bar (default) — a per-query bar at the null_p(level) + offset of 200 seeded random target neurons. Cross-dataset morph scores have a high, query-dependent baseline, so only the distance above the noise floor is meaningful.
    • Mapping-referenced floor (floors v3) — when the queried type resolves in the cross-dataset type mapper, the bar comes from the mapper's target-side branch pools instead: the pool's mean self-similarity minus a margin (native, ≥ 2 references required) binds; otherwise the query's mean similarity to the pool minus the offset (B_b − Δ); sources without a mapping fall back to the null bar. Needs a cross-dataset pair — the option is disabled when Target = Source (same-dataset runs use the null bar).
  • Level (percentile, default p95) — which percentile of the null distribution the bar sits at; p90/p75 loosen the bar for review, p99 tightens it.
  • Candidates below the bar are excluded from the 3D scene and reported; the results tables keep every row and gain morph_v2, morph_null_p95, morph_z, morph_bar_kind, morph_bar, morph_null_level and morph_qualified columns on the scored rows.
  • The bar offset slider raises the bar above the null level for a stricter confirmation. With the option off, output is byte-identical to the classic behavior.

Loose search (more candidates)

The loose-search knobs (Min Shared Partners, Candidate Prune %), formerly exposed by the removed "Connectivity similarity" mode of the old Find Similar tab, are no longer in the UI — the default discovery settings cover the intra-dataset search. The backend parameters (min_shared_partners, vector_prune_fraction) remain supported programmatically: lower the shared-partner threshold (1 = any shared partner) and raise the prune fraction (1.0 = keep all cosine-positive candidates) to widen the candidate pool while keeping the same adjacency-expansion hops.

Output

Each run is saved in its own timestamped folder named after the query and the dataset abbreviations (MCNS = male-cns, FAFB = flywire FAFB, ...); the Save Folder Name field overrides this:

{output_dir}/homologs_MCNS_to_FAFB_aMe12_20260815_143540/
  README.txt
  results/
    homolog_results.csv          # full ranked results (all metrics)
    bodyid_results.csv           # bodyId-level results
    type_summary.csv             # type-level summary
    type_level_results.csv       # pooled type-level ranking (top N per source type)
    source_status_summary.json   # per-source-neuron status
  profiles/
    query/{type}.csv, query/source_bodyids.csv
    matches/{type}.csv, matches/top_target_bodyids.csv
  overlaps/{source}_vs_{target}.csv    # partner overlap details
  visualization/...            (when visualization enabled)

BodyId-level tables (results/bodyid_results.csv, profiles/query/source_bodyids.csv, profiles/matches/top_target_bodyids.csv) list the neuron's instance next to its type, resolved from that row's dataset neuron table (empty when the neuron is unknown to it) — no bodyId-level export identifies a neuron by its bare numeric id alone.

Exported run guide: every successful run also writes _UserGuide_please_read_me.html into the run folder — a self-contained explanation of every output file, every table column, and any warnings recorded for the run. Format (html / txt / markdown / disabled) is set in Settings → Default Settings → Run Guide Format.
