Pathfinding Algorithms

How DROCAT finds multi-hop pathways and how runs are bounded. StrongestFirst is the built-in 'all'-mode algorithm — the Algorithm selector was removed on 2026-09-05. The other enumerators below remain available to scripts via the pathfinding parameter and are kept here for the benchmark record.

StrongestFirst (budgeted) — the pipeline algorithm

pathfinding='StrongestFirst' · FastGraph.find_paths_strongest_first

Best-first search ordered by each path's bottleneck (its weakest edge), with a widest-path backward DP as the admissible bound. Emits complete intact paths strongest-first under a path budget (Max Paths (BodyId), max_paths_bodyid; 0 = auto → internal 1,000,000 budget): when the budget is reached the search drains every tie at the cutoff strength tau and stops, so the output contains exactly "all intact paths with bottleneck ≥ tau" (the drain may overshoot the budget — both numbers are reported). Without a budget bite the emitted set is identical to the complete enumerators, and the run reports its natural tau — the weakest emitted path's bottleneck ("every threshold up to this value yields this identical set").

Two lossless prunes (hop-budget edge pruning, iterated to a fixpoint, + dead-end node pruning) shrink the cone before enumeration. A lossy Edge Budget (graph_edge_limit_bodyid, default 1M, 0 = off) caps the cone itself: when the lossless-pruned cone still exceeds the budget, the budget-fit search floors it at the weakest weight tier whose closed cone fits the cap (t*) — exactly equivalent to raising the threshold to t*, the applied floor is reported as edge_weight_floor (effective cutoff = max(tau, t*)), and the residual slack plus probe trace are recorded. When even the full closed cone fits the cap, no floor is applied. Shortest mode is never floored.

What "pathfinding" means here

Given a set of source neurons and a set of target neurons, DROCAT enumerates every acyclic connection chain (path) from any source to any target with at most Max Intermediate Layers + 1 edges (the cutoff). All five algorithms return exactly the same paths — they only differ in how fast they run and how much memory they use.

Path counting is exponential in the cutoff (each extra hop multiplies the search by the average branching factor), so the algorithm choice matters most for deep queries (3+ intermediate layers) on dense connectomes.

The complete enumerators (API / benchmark reference)

All of these return exactly the same path set as an unbudgeted StrongestFirst run — they differ only in speed and memory. They are no longer selectable in the UI; scripts can still set pathfinding='MemoizedDFS' (etc.) with max_paths_bodyid=0 for unbounded complete enumeration, which is also exactly what a τ-clamped run equals at its reported tau.

DP (Backward Reachability)

First computes which nodes can reach a target within the cutoff (backward DP layers), then runs a forward search that only follows edges that provably lead to a target.

Strongest dead-end pruning; stores only node sets. Fastest measured at 3 intermediate layers (0.02 s) with low, flat memory. Degrades on very deep (5+) queries. Not the default — MemoizedDFS is.

DFS (Backward Memoized)

A standard depth-first traversal from the targets, remembering which nodes can still reach a source at each remaining depth.

Moderate memory. Fastest at 4 intermediate layers and the best time-memory tradeoff at 5, when the target group is small (the backward direction starts from the smaller set).

Best for: deep paths with few targets.

MemoizedDFS (Forward Memoized)

A depth-first traversal from the sources that remembers which successors can still reach a target at each remaining depth, so each (node, depth) state is computed once.

Moderate memory and no reversed-graph copy — the memo is built from the sources and pruned to successors that can reach a target, so the search stays inside the source-side cone. Fastest at 4 intermediate layers; the default.

Best for: balanced queries; deep paths with many targets.

MeetInMiddle (Meet-in-the-Middle)

Stores all half-paths up to the middle depth from the sources, then walks backward from the targets and stitches matching halves.

Fastest at shallow depths (2–3 layers), but its half-path table is rebuilt for every length and the pairwise stitching costs more than a fully-pruned shared memo on real connectomes — so it is not the deep-path winner its design suggests.

Best for: shallow queries; a safe middle ground at 4+ layers.

Bidirectional (BFS)

Searches forward from sources and backward from targets at the same time, then stitches the two half-trees at the middle layer.

Shortest-first emission order (the path set is identical to every other complete enumerator). Highest memory: stores the full search trees from both sides, and memory grows with the cutoff (452 MB at 4 layers, 1.1 GB at 5 on a small query). The extra memory buys a smaller search frontier, but not faster enumeration: its path stitching copies lists at every depth and builds sets per candidate pair, so it is the most expensive per path of all four (measured 10.4 µs/path vs 1.8 for DFS/DP on a controlled graph) — the classic bidirectional win only applies to shortest-path search, where you can stop at the first meeting.

Best for: shallow API queries where you want shortest-first ordering and memory is not a concern. Note the Shortest Paths tab does not use it — that tab runs the target-rooted StrongestFirst enumerator find_paths_shortest_strongest_first (see below).

The Shortest Paths tab

The Shortest Paths tab does not use any 'all'-mode enumerator above. It enumerates through FastGraph.find_paths_shortest_strongest_first: a per-target reverse BFS outlines the min-hop DAG, a maximin bottleneck DP annotates every branch with the best achievable strength, and tied shortest paths are emitted best-first in strength order with a k-way merge across targets. The Max Paths (BodyId) budget bounds it exactly like an 'all'-mode run — a bitten run is tau-bounded ("all min-hop paths with bottleneck ≥ tau") — and the Edge Budget never applies: shortest mode is never floored. (The find_paths_shortest_backward exporter also exists in FastGraph, but the pipeline does not call it.)

They compose exactly: effective cutoff = max(tau_budget, t*), and the run equals a complete run at that threshold. A complete run reports its natural tau (weakest emitted bottleneck) — every threshold up to that value yields the identical set. The Drop Untyped Neurons checkbox is a neuron-label filter, not a bound: it removes edges touching untyped labels (empty / Unknown / NaN / bodyId-fallback) before the graph is built and is distinct from graph budgets, path budgets and the drawing cap.

Every run consolidates these into an applied-threshold provenance block written to parameters.txt, all_attributes.json and data_details/parameters.csv: requested_threshold, applied_threshold, applied_threshold_source ('requested' | 'strongest_first_budget' | 'edge_budget' | 'strongest_first_budget+edge_budget'), strongest_first_budget (auto 1,000,000) with strongest_first_budget_bitten, strongest_first_tau (the landing tau), tau_canonical, strongest_dropped_bottleneck (w2 — the strongest path NOT kept), edge_budget_applied, edge_budget_landing (w1), edge_weight_floor (w0), strongest_retained_bottleneck (W* — the widest-path ceiling after lossless pruning; lossless pruning never changes it) and paths_complete. When a gap exists between w2 and tau, every threshold in [w2+1, tau] yields the identical set and w2+1 (= tau_canonical) is the minimal equivalent; for an unbounded run applied_threshold stays at the requested threshold and the natural tau is reported separately. A budgeted output is a strength-bounded path set, never an arbitrary first-N truncation.

Practical tips

  • Prefilter the graph: raising Min Synapse Count and lowering the Edge Budget shrinks the search space far more than any other control.
  • Deep + dense = expensive: the number of paths grows exponentially with Max Intermediate Layers; the output itself dominates runtime and memory once path counts reach millions — that is what Max Paths bounds, with a reported tau.
  • Clamping is honest: a τ-clamped run equals a complete run at its reported tau (complete enumerators — API only — reproduce the identical set when run at that threshold).
