Comparison Morphology tab

Compare the morphology of already-identified neurons within one dataset: enter neurons, types, taxonomy labels, or patterns and get the N×N similarity matrix at the bodyId level plus a type-level aggregation, with interactive heatmaps and a summary report.

One dataset = intra-dataset. Skeletons are scored in one dataset's coordinate space against that dataset's caches. Select two or more datasets to switch this sub-tab into the cross-dataset comparison (queried neurons across FAFB / male-cns / BANC, null-baselined vector_v2).

Quick start

  1. Pick the Datasets to compare (multi-select; BANC runs with an explicit caveat — the public L2/full skeleton products' vector quality is still unvalidated, so treat BANC scores as provisional and spot-check surprising pairs in the 3D scene; BANC 3D visualization and pathfinding work).
  2. Enter one or more query tokens: exact types, bodyIds, taxonomy labels (e.g. FAFB's circadian_clock), instance names, or patterns (e.g. aMe.*) — or pick custom group as the Aggregation Level and define the groups on the grouping board instead.
  3. Choose the Aggregation Level (type / bodyid / custom group) in Advanced Settings to decide what one matrix row is.
  4. Click Run Comparison; open report.html in the output folder.
The gate is neurons, not rows. A run needs at least two neurons in scope, so one type is a legitimate comparison: its aggregate cell is that type's own cohesion (the mean pairwise score among its members, not 1.0) and the bodyId matrix carries the pairwise detail. One query that resolves to a single neuron is refused, with the message naming what collapsed it — the query itself, or Max Members per Type being below 2 at the bodyId level.
How each query token resolves. Tokens resolve in the same order the Connectivity ▸ Comparison tab uses: exact type name → bodyId → taxonomy label (a cell_type / class value such as FAFB's circadian_clock expands into one row per member type) → instance name (those neurons are pinned, like bodyId inputs) → pattern. Every expansion, pin, cap, and unmatched token is disclosed in the run folder's user_warning_notes.txt and in the run log, so a query that resolved through an expansion never looks like a literal-type run.

Aggregation Level — what one matrix row is

  • type (default): each queried type is one row; a bodyId input resolves to its type. The bodyId-level matrix is written alongside.
  • bodyid: every individual neuron is its own row, so two neurons of the same type can be compared — the thing the type level folds away. Here the bodyId matrix is the comparison, so no type-level matrix or heatmap is produced, and the report carries no tab for it — a tab that can only ever read "not computed" invites the reader to look for a missing input rather than a deliberate level. Not offered while the method is NBLAST (see below).
  • custom group: rows are the source-side groups of the grouping board (a saved preset or groups defined inline), resolved against the selected dataset; the neuron query above is disabled, not silently ignored. Same board and preset format as Connectivity ▸ Comparison. The aggregate matrix is written as group_level/group_similarity_{method}.csv with heatmap_group_*.html, because its axes are groups, not types.

How the comparison works

  • The bodyId-level matrix is always the scored primitive: every individual pair, labelled {bodyId}_{instance} (or {bodyId}_{type}_L/_R on FAFB).
  • The aggregate matrix (type or group level) is derived from it: each entry is the mean over the cross-member bodyId pairs, and the diagonal is that row's intra-type/group cohesion (mean pairwise among its own members, 1.0 for a single-member row).
  • A neuron you queried by bodyId is never dropped by Max Members per Type or Max Total Neurons; those caps only remove other members. members.csv lists every compared neuron with the row it fed and its real type.

Methods

MethodCostNotes
Vector (spatial) — defaultFast (cached vectors) The Find Similar production score: per-block cosine (shape/spatial 0.30/0.70) on standardized + ZCA-whitened vectors from the dataset's vector cache. Missing members are fetched online by default — NeuPrint raw SWC via the shared batch fetch, FAFB via the healed bundle → CAVE fallback — and persist into the shared skeleton + vector caches. Mirror twins are legitimate evidence (lateral normalization).
NBLASTSlow — warns on populations over 30 neurons, never refuses Canonical normalized NBLAST on raw-skeleton dotprops; both orientations of every pair are scored and averaged. Large populations are disclosed as slow in the run log and user_warning_notes.txt rather than gated. Aggregate means exclude contralateral pairs (mirror arbors score at chance); the bodyId matrix keeps every pair. Because every neuron enters scoring, the Aggregation Level drops bodyid while NBLAST is selected — there each row is one neuron, so a realistic query could not complete.

3D skeleton scene

With 3D Skeleton Visualization enabled, the run also renders the compared population into plot-3d_{dataset}/ inside the run folder: one skeleton layer per compared matrix row (capped at 20 members per row for the render, with an in-page note when a layer is sampled), line skeletons on a template brain, no synapses. The scene is linked from report.html, and the legend tree lists every neuron leaf.

report.html uses the same tabbed generator as the connectivity-profiling and cross-dataset morphology reports (shared report_kit): a hero header, Type-level / BodyId-level tabs with Ward-clustered heatmap cards (hover for exact values, CSV and VisPath editor links), and compared-neuron / parameter details. Every heatmap card's cells render square (1:1, at any window size) — the card itself is not squared, only the matrix cells. Plotly.js is embedded, so the report renders offline. vector_v2 renders on a diverging blue–white–red scale (a whitened cosine can be negative); NBLAST stays on the positive [0, 1] scale.

BodyId-level rows and axes are labeled {bodyId}_{instance} (NeuPrint-style datasets, e.g. 11309_aMe4_L) or {bodyId}_{type}_L/_R (FAFB/BANC) — the same labels the 3D legend tree uses — so no export reads as a bare numeric id. members.csv maps every label back to its raw bodyId.

Neurons that stay unavailable even after the online fetch (no skeleton at the source) are reported in members.csv (no vector / no dotprops) and carry empty matrix cells instead of silently biasing the averages.

Exported run guide: every successful run also writes _UserGuide_please_read_me.html into the run folder — a self-contained explanation of every output file, every table column, and any warnings recorded for the run. Format (html / txt / markdown / disabled) is set in Settings → Default Settings → Run Guide Format.
