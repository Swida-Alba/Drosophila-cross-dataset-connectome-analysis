Comparison Morphology tab

Compare the morphology of already-identified neurons within one dataset: enter 2+ neurons (types, bodyIds, or patterns) and get the N×N similarity matrix at the bodyId level plus a type-level aggregation, with interactive heatmaps and a summary report.

One dataset = intra-dataset. Skeletons are scored in one dataset's coordinate space against that dataset's caches. Select two or more datasets to switch this sub-tab into the cross-dataset comparison (queried neurons across FAFB / male-cns / BANC, null-baselined vector_v2).

Quick start

  1. Pick the Datasets to compare (multi-select; BANC is unavailable — morphological comparison is deferred there pending vector-quality validation of the public L2/full skeletons, not because skeletons are missing; BANC 3D visualization and pathfinding work).
  2. Enter 2+ neurons: exact types, bodyIds, or patterns (e.g. aMe.*).
  3. Click Run Comparison; open report.html in the output folder.

How the comparison works

  • Each queried type is one row of the matrices; its members supply the pairwise scores. bodyId inputs resolve to their type.
  • BodyId-level matrix: every individual pair.
  • Type-level matrix: each entry is the mean over the cross-member bodyId pairs; the diagonal is the type's intra-type cohesion (mean pairwise among its own members, 1.0 for a single-member type).

Methods

MethodCostNotes
Vector (spatial) — defaultFast (cached vectors) The Find Similar production score: per-block cosine (shape/spatial 0.30/0.70) on standardized + ZCA-whitened vectors from the dataset's vector cache. Missing members are fetched online by default — NeuPrint raw SWC via the shared batch fetch, FAFB via the healed bundle → CAVE fallback — and persist into the shared skeleton + vector caches. Mirror twins are legitimate evidence (lateral normalization).
NBLASTSlow — capped at 30 total neurons Canonical normalized NBLAST on raw-skeleton dotprops; both orientations of every pair are scored and averaged. Type means exclude contralateral pairs (mirror arbors score at chance); the bodyId matrix keeps every pair.

3D skeleton scene

With 3D Skeleton Visualization enabled, the run also renders the compared population into plot-3d_{dataset}/ inside the run folder: one skeleton layer per compared type (capped at 20 members per type for the render, with an in-page note when a layer is sampled), line skeletons on a template brain, no synapses. The scene is linked from report.html, and the legend tree lists every neuron leaf.

report.html uses the same tabbed generator as the connectivity-profiling and cross-dataset morphology reports (shared report_kit): a hero header, Type-level / BodyId-level tabs with Ward-clustered heatmap cards (hover for exact values, CSV and VisPath editor links), and compared-neuron / parameter details. Plotly.js is embedded, so the report renders offline. vector_v2 renders on a diverging blue–white–red scale (a whitened cosine can be negative); NBLAST stays on the positive [0, 1] scale.

BodyId-level rows and axes are labeled {bodyId}_{instance} (NeuPrint-style datasets, e.g. 11309_aMe4_L) or {bodyId}_{type}_L/_R (FAFB/BANC) — the same labels the 3D legend tree uses — so no export reads as a bare numeric id. members.csv maps every label back to its raw bodyId.

Neurons that stay unavailable even after the online fetch (no skeleton at the source) are reported in members.csv (no vector / no dotprops) and carry empty matrix cells instead of silently biasing the averages.

Exported run guide: every successful run also writes _UserGuide_please_read_me.html into the run folder — a self-contained explanation of every output file, every table column, and any warnings recorded for the run. Format (html / txt / markdown / disabled) is set in Settings → Default Settings → Run Guide Format.
