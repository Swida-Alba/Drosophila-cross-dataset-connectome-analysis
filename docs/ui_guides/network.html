Net-Viz (PlotPath)

The Net-Viz tab turns pathway data into interactive graphs: a Sankey flow diagram, a connection heatmap and a draggable Cytoscape network, plus an editable empty drawing canvas. It runs vispath_pkg.VisualizePath in the background. For neuron morphology see the separate 3D Skeleton guide.

Quick start - path network

  1. Run Complete Paths first.
  2. Upload its *_allpaths_type.csv (or *_allpaths_info.xlsx) file.
  3. Click Generate Network.

Quick start - edge list editor

  1. Select the Edge list editor button at the top of the Net-Viz Source card (it is the default mode; opening the editor also selects it). The editor table appears below the three source buttons.
  2. Type straight into the table cells (the editor starts with three empty rows), or click Add Row for more. Enter a Draft Name to turn on auto-save, or leave it empty to run without a draft.
  3. Click Generate Network - a named draft is auto-saved and used directly as the network input; an unnamed table runs from a temporary CSV.

Quick start - empty drawing canvas

  1. Select the Empty canvas button in the Net-Viz Source card and click Create Empty Canvas (pressing Generate Network in this mode does the same); no path file is required. It generates the HTML and opens it in a new browser tab automatically.
  2. Enable Edit Mode, add nodes, and connect them directly on the canvas.

Network input files - full specification

The upload button accepts CSV, XLSX and XLS files. The backend (VisualizePath) auto-detects one of three data formats inside the file, so you can feed it Complete Paths output, a simple edge list, or a connection matrix. Only one file is loaded at a time; uploading a new file replaces the previous one.

Format 1 - Path-based (Complete Paths output)

Each row is one complete multi-hop path. This is the format produced by the Complete Paths tab.

ColumnRequiredAccepted namesMeaning
Path yes path_block, path, path_str Ordered node sequence, e.g. A->B->C. Aliases are renamed to path_block automatically.
Weights yes weights List of per-hop weights (synapse counts), e.g. [10, 5]. Length must equal number of nodes − 1.
Connection ratios optional connection_ratios, ratio, ratios, connection_ratio, conn_ratio Per-hop connection ratios (case-insensitive match).
Traversal probabilities optional traversal_probabilities, probability, probabilities, prob, traversal_probability, trav_prob Per-hop traversal probabilities (case-insensitive match).
Layer optional layer Layer annotation kept for downstream analysis.
Minimal path-based CSV
path,weights
aMe12->aMe10->MBON01,"[128, 47]"
aMe12->PPL101->MBON01,"[63, 22]"

Two 2-hop paths. Weights are the synapse counts of each hop; here min_weight would be 47 and 22 respectively.

Complete Paths files at a glance

FileContent
{source}_to_{target}_allpaths_type.csv Type-level paths (recommended for visualization).
{source}_to_{target}_allpaths_bodyId_paths.csv bodyId-level paths (finer grain, more rows).
{source}_to_{target}_allpaths_info.xlsx Excel workbook; the path_type / path_bodyId sheets hold the same tables.

Columns of the path tables: path_str (node list), path (A->B->C string), weights, probabilities, ratios, min_weight (bottleneck synapse count), path_prob (product of hop probabilities), min_ratio, length (number of hops). Extra columns are ignored, so the files can be filtered/sorted (e.g. keep only rows with min_weight ≥ 10) and re-uploaded as-is.

Format 2 - Edge list

Each row is one directed connection; the network is built directly from the edges (every edge becomes a 1-hop path). Detection accepts these column sets:

  • source / target / weight
  • from / to / weight
  • pre / post / weight
  • Any {prefix}_pre + {prefix}_post + weight combination, e.g. bodyId_pre, bodyId_post, weight (the connection tables cached by DROCAT use this layout).

The weight column may also be named weights, synapse_count or count. An optional color / edge_color / link_color column assigns a per-edge color (hex or rgba).

Expanded edge list (Edge List CSV export). The file written by the in-HTML 📋 Edge List CSV button (see Export edge list as CSV) can be re-uploaded as-is - it round-trips back into the same network. The extra columns are handled as follows:

ColumnOn re-import
source / target / weight Required; the edges of the network (signed weights allowed).
color Per-edge color (hex or rgba).
nt_type Neurotransmitter type; drives NT-based edge coloring (empty = unknown).
source_group / target_group Restores the source / intermediate / target classification of each endpoint node. Without them a plain edge list would classify every node as source. Any other value turns that endpoint into a custom group: it gets a legend chip, a quick-select button and an entry in the group dropdown, and keeps its structural role (source / intermediate / target) as a subtitle.
edge info / source info / target info Hover labels as {key:val; ...} cells: per-edge custom labels and a per-node union of the source/target info. Shown in the network tooltips.
ratio / probability Mapped back to the standard connection-ratio and traversal-probability metric columns.
nt_group / custom_groups Informational; accepted and ignored (NT grouping is re-derived from nt_type).

Enriched edge lists - authoring complex graphs

The edge list grows far beyond source, target, weight: every optional column above adds renderer features — per-edge colors, custom node groups (source_group / target_group, any name you like), hover-label info (edge info / source info / target info as {key:val; ...} cells), neurotransmitter annotations (nt_type, shown on edge hover) and extra numeric metrics such as ratio / probability (toggleable on the edges in the network). A declared-bidirectional column (bidirectional or bidirectional_pair) marks rows that traverse both ways: a flagged single row becomes one double-headed edge whose weight stands for both directions, and two rows sharing the same pair id merge into one double-headed edge with their respective weights (the exact shape the Edge List CSV export writes for merged pairs).

Edit complex enriched graphs in a local CSV file Typing this metadata into the in-page table does not scale. For graphs with hover-label info, custom groups or more columns, author the edge list in a local CSV file (any spreadsheet/CSV editor), then either import it into the edge list editor with its upload button to keep editing, or run it directly through the File upload source. The Auto Type Mapping network views showcase these features — dataset legend chips, per-node hover annotations, per-edge maps via hover labels and custom node groups (see the Type Mapping panel guide).

Every optional column may be left empty per row (see color and edge info in row 3, custom_groups in row 2). source_group / target_group accept the structural roles (source, intermediate, target) or any free-form custom group name — row 3 tags PPL101 with a salient group, which renders a legend chip and quick-select button while keeping its structural role in the hover. nt_type/nt_group annotate the neurotransmitter (hover text; NT edge coloring is used by the pathfinding pipelines); custom_groups preserves in-HTML group names on round-trip; and the info cells are {key:val; ...} hover labels whose values must not contain semicolons.

Format 3 - Connection matrix

A 2D numeric table where rows are pre-synaptic and columns are post-synaptic nodes. Every non-zero cell becomes an edge. In a CSV the first text column is used as the row labels; column headers are the target labels. If labels are missing, nodes are named N0, N1, ....

Matrix CSV
,aMe10,PPL101,MBON01
aMe12,0,63,0
aMe10,0,0,47
PPL101,0,0,22

Excel sheet selection

For workbooks the sheet is chosen automatically in this priority order: path_type → path_bodyId → path_block → paths. A workbook with a single sheet uses that sheet; any other sheet layout falls back to the first sheet when run from the UI. For CSV files no sheet selection applies.

Common mistakes - Uploading a path file with a path column but no weights column (both are required). - A weights list whose length does not match the number of hops (nodes − 1). - Saving CSV with BOM/UTF-16 - use UTF-8. - Expecting an edge list named pre_syn/post_syn to work without a weight column.

Edge list editor - auto-save & recovery

The editor builds a Format-2 edge list interactively (the same inline-editing model as the Skeleton tab's Advanced Layer Editor) and persists changes automatically:

  • Inline editing: type straight into the table cells; every cell commits on blur, Enter or Tab. Add Row appends an empty row and Delete Selected removes the checked rows (three empty rows are always kept as scaffolding). A Columns switch exposes the extended group / hover-info columns (source_group, target_group, edge info, source info, target info), and the color cells have a swatch that opens a color picker. Column widths can be drag-resized from the header. For large or metadata-heavy edge lists, prefer authoring a local CSV file — see Enriched edge lists.
  • CSV import: the upload button next to Export CSV loads an edge-list CSV into the table for continued editing (the editor's own export or the expanded in-HTML export both work).
  • Auto-save: once the table holds at least five filled rows, edits are flushed atomically about half a second after the last commit to local_data/edge_list_drafts/ ({name}.csv + a metadata sidecar) — but only when a Draft Name is entered. A handful of half-typed rows is deliberately not persisted; running or exporting always flushes explicitly. Renaming a draft moves it (the old draft is removed).
  • Validation: errors (missing source/target, non-numeric or negative weight) are listed in a panel inside the editor when you run or export. Exporting still downloads the CSV with a warning; Generate Network is blocked until the errors are fixed.
  • Running: in the Edge list editor mode, Generate Network flushes the named draft (or writes a temporary CSV when unnamed) and feeds it straight to PlotPath, so the table must contain at least one complete edge (source, target, weight).
  • Export CSV downloads the draft as {name}_edge_list_{timestamp}.csv through the browser. Optional columns are written only when at least one row uses them. The pending-export marker is cleared.

Rendering options

  • Source buttons: Edge list editor (build/edit an auto-saved edge list; default), Empty canvas (create an empty drawing canvas with the Create Empty Canvas button or the main run button), or File upload (load Complete Paths output or any format above).
  • Path Output Directory: every run creates its own plot-network_{name}_{timestamp}/ subfolder inside it.
  • Network Layout: hierarchical (default), spring, circular, shell, or distributed.
  • Color Scheme: swatch-preview presets (Cool, Default, Warm, Purple) for source / intermediate / target nodes and links.
  • Node Shape: circles (default), round squares or sharp squares; By Role draws source/target as round squares and intermediates as sharp squares (flowchart convention).
  • Merge Bidirectional Edges: collapse reciprocal pairs (A→B + B→A) into one double-headed edge. Width uses the stronger direction; hovering shows both.
  • Open in Browser: open the HTML results right after the run.

The network view shows at most the 500 strongest edges (source/target connections are always kept); the exported data files always contain the complete table.

Working with the generated network HTML

  • Explore: drag nodes, hover for weight/probability tooltips, click a node or edge to highlight its neighborhood, right-click to hide elements.
  • Adjust: live sliders for node size, font size and edge width; a Node Shape dropdown (circle / round square / sharp square - a global override like the Node Size slider); toggle orphan nodes, self-loops and dead ends; re-run the layout.
  • Merged bidirectional edges: when generated with the merge option (or from an edge list with a bidirectional column), a reciprocal pair renders as ONE edge with arrowheads at both ends. Width and the weight-band filter use the stronger direction; hover and the Edge List CSV export show both directions.
  • Color: restyle selected elements or whole groups (source / intermediate / target nodes, all edges).
  • Edit Mode (empty canvas): add nodes, drag from one node to another to connect them, double-click to edit properties (label, type, color), right-click to delete. Every action is recorded - use Undo/Redo or the history list to jump between states.
  • Per-node size & shape: with an element selected, the Position / Size panel exposes X/Y, independent W/H (px), and a per-node Shape dropdown (Circle / Round Square / Sharp Square; Follow Global drops the override so the ribbon Node Shape applies again). Every field applies immediately on change (the ribbon Sizes pattern) and targets the whole selection: X/Y moves the primary exactly and the other selected nodes follow by the same delta; W/H resize every selected node. When the selection disagrees on a size, the field shows mixed - typing a value overwrites it, an empty one keeps each node's own. The 🔗 aspect-ratio lock scales H from the captured ratio while W changes.
  • Arrow-key nudging: arrow keys move the selected nodes by 1 px (Shift = 10 px); a rapid burst coalesces into one undoable Nudge nodes entry.
  • Align & Distribute: ⇔ Align H / ⇕ Align V put the selected nodes on the shared mean Y / X (2+ nodes); ⇔ Dist H / ⇕ Dist V spread them evenly along X / Y between the two extreme nodes, which keep their positions (3+ nodes). A Gap (px) value switches distribution to fixed center-to-center spacing (the first node anchors, the last moves).
  • Match size / Reset size: ⤢ Match size copies the primary node's W×H to the other selected nodes; ↺ Reset size clears per-element size overrides so the global Node Size / Edge Width controls apply again.
  • Z-order: ⬆ Front / ⬇ Back layer the selected elements above/below everything else.
  • Persistence: Save/Load and Export/Import Layout carry all of it - explicit sizes, per-node shapes, z-order and manual edge widths (absence = follow the global controls).
  • Save your work: Save/Load the full view state (positions, colors + alpha, groups, filters, controls — auto-restored when the file reopens), Export/Import it as JSON (legacy positions-only files import too), Export/Import the graph, export the edge list as CSV, and export the figure as PNG or SVG.

Export edge list as CSV

The 📋 Edge List CSV button in the Export panel downloads every edge of the current graph - including everything changed in Edit Mode (edited weights, recolored edges, added/deleted edges, relabeled nodes). The file always contains the complete edge table, even when the view is filtered or elements are hidden. The file is a valid Format-2 edge list: upload it again in the Net-Viz tab to rebuild the same network (edges, colors, NT types, metric columns and the source/intermediate/target node grouping).

ColumnContent
source / target / weight Edge endpoints (current node labels) and the signed weight - directly re-importable as a Format-2 edge list.
color The edge's current color (hex); recognized on re-import.
nt_type / nt_group Neurotransmitter type and its group (excitatory / inhibitory / modulatory / unknown). nt_type is recognized on re-import.
source_group / target_group Node group of each endpoint (source / intermediate / target).
custom_groups Semicolon-separated names of custom groups containing the edge.
ratio / probability Connection ratio and traversal probability when present; empty otherwise. Mapped back to the standard metric columns on re-import.
bidirectional_pair Pair id (A<->B) marking both-way edges. A merged double-headed edge exports as its two directional rows sharing the id, so re-import rebuilds the merged edge with both weights.
