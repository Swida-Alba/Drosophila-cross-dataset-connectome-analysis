Cross-Dataset Comparison

This guide covers the Paths tab, now grouped under Cross-Dataset beside Type Validation (which validates a type mapping at the bodyId level).

Analyze one dataset across multiple synapse thresholds, or compare connectivity between two or more datasets (e.g. male-cns:v0.9 vs hemibrain:v1.2.1) for the same source → target query.

Threshold basis: on weight_basis='connection_ratio' runs the edge weight is the F9 connection ratio (synapses / the post neuron's total incoming at min_weight=1) — the threshold, Edge Budget tiers and StrongestFirst bottlenecks are in ratio units; every synapse column is unchanged. Auto mode also runs on float ratio tiers: the density bootstrap and alignment use float64 ratio arrays and distinct-tier ladders. See docs/core-features/ConnectionRatioPaths.md.

Quick start

  1. Select one or more Datasets. The dropdown opens with a Recommended section (male-cns:v1.0, flywire_FAFB_v783, banc_v888), followed by an Available section listing every dataset grouped by source (NeuPrint, then FAFB, then BANC) and sorted by name within each source — the recommended three repeat there, and selecting either copy toggles the same dataset. One dataset with multiple thresholds is also supported; select multiple datasets for cross-dataset comparison.
  2. Add Source Neurons and Target Neurons.
  3. Click Run Comparison - a report plus matrices are produced for every threshold.
Release recommendation: if you select male-cns:v0.9 while male-cns:v1.0 is available, the selector shows an in-page notice recommending the newer release for current type mapping. Choose Use male-cns:v1.0 deliberately to replace it, or keep v0.9 for legacy/reproducible runs. The notice never changes a selection silently and disappears when v1.0 is already selected or is not available in the current options.

Inputs & examples

The Source Neurons and Target Neurons boxes accept one query per chip (exact / starts with / contains / ends with / regex) and help while you type: dataset-aware suggestions list matching type / instance / bodyId names with a gray hint naming the matched column and dataset (type · male-cns:v1.0). Picking a row adds the chip and only then clears what you typed, while that query's rows stay listed in the same order: a name you already added is tinted and ticked rather than dropped, so the list never shifts under the cursor and you can keep clicking through it without retyping — type PPL1, pick PPL101, then PPL102. Clicking a ticked row takes that chip back out, exactly as the chip's own x does, so a marked row works as a checkbox in either list. With the field empty, the Recent/Frequent history lists your previously run queries — it carries the same marks, and its small × — which appears only while that row is hovered, so it cannot be confused with the tick — is the other action, dropping the entry from the history while keeping the chip — and the list is click-to-toggle: clicking the focused field again hides it, clicking once more brings it back (clicking a row still toggles its chip, and clicks on chips or their × buttons never toggle the list). A click that closes a held suggestion list ends that query too, so the next opening shows the history instead; clicking outside the box, pressing ESC or typing new text do the same. Long chip lists collapse into a scrollable view; Expand shows every chip and Collapse restores the compact view — in both states the chips scroll inside the field border and never render outside it. Each history row carries one gray tag per selected dataset whose local neuron pool actually contains the value — a male-cns-only type such as 5thsLNv_LNd6 is tagged male-cns:v1.0 only, never the other datasets that merely shared the same run. Values that resolve in none of the selected datasets (regex patterns, names only in datasets without local tables) show no tags. The Recent/Frequent list itself stays scoped to your selection: a query recorded only for datasets you have deselected is hidden until you select one of them again. Both boxes also accept an upload (CSV / TSV / XLSX / XLS, first column is read — see the input formats guide).

Threshold query table

Use Standard for the historical same-threshold comparison. Switch to Custom combination when one cross-dataset query needs different thresholds. It requires at least two selected datasets. The query editor uses one column per selected dataset and one row per query; every cell must be a positive integer. Rows receive stable IDs such as combo_001. Add combination appends a row, each row carries a remove button, and Suggest from alignment prefills rows with density-equivalent thresholds read from a completed run's comparison_results/suggested_threshold_combinations.json. This replaces the old Advanced Settings per-dataset schedule. A dataset's cells across rows are not a custom schedule to compare independently: the row is the unit of alignment, similarity, report, and provenance.

The raw jobs are deduplicated across rows. For example, rows (BANC=3, FAFB=7) and (BANC=5, FAFB=7) reuse the FAFB@7 raw run but remain two distinct comparison queries.

Auto is the default mode (listed first; it covers both the per-threshold and the density-aligned comparison, so no threshold chips are needed). It runs one bootstrap enumeration per dataset at the floor (Min Synapse Count 3), measures each dataset's completeness window [w_start, w_star_measured] from the query's own searched graph (the ceiling is the measured max(path bottlenecks), not the stored provenance value), and then emits integer aligned rows: vertical rows share one threshold across all datasets, horizontal rows share a normalized edge density E(t)/N (N = typed searched nodes, fixed in t). Vertical rows are named threshold={N} and horizontal rows aligned_density={level} — these ids are the tab buttons, the report card headers, and the keys inside threshold_combinations.csv and the per-query export filenames (e.g. conserved_network_threshold_19_network.html; two density levels that round to the same name get a _2 suffix). The rows feed the same combination engine, so the comparison runs end-to-end with no new pathfinder. A dataset without a density capture is excluded from the horizontal rows instead of vetoing them: those rows carry a partial_datasets marker, the run notes log a [density partial] line, and the report labels them. The report's density section embeds the curves as an interactive Plotly chart — grey dashed vertical guides mark the vertical rows' thresholds, grey dotted horizontal guides the horizontal rows' density levels; hover either guide for its row id. Outputs: comparison_results/density_curves.csv, density_windows.csv, and density_alignment_best_matches.csv; the run guide (_UserGuide_please_read_me) mirrors the auto warnings.

Auto mode resolves in one of three ways, and never quietly: installed (every dataset measured — vertical spine plus the density-matched rows), verticals_only (a dataset could not be measured, so the horizontal rows are exported for reference but not run; the aligned-rows card names those advisory ids), or degraded (no schedule could be measured, so the requested thresholds run as-is and the density section is bannered red). The outcome and its per-dataset reasons are written to user_warning_notes.txt and to run_manifest.json → auto_mode_status, and a failed neuron cache marker no longer costs the measurement behind it — it costs a later re-fetch of those neurons only.

Density curves are not exclusive to auto mode: every pathfinding comparison exports density_curves.csv and density_windows.csv for every queried dataset, spanning its own window from the minimal available threshold to the measured ceiling, computed on the cone (the searched graph at the lowest executed threshold). The edge basis follows the Drop Untyped setting (bodyId_edges_typed when on, bodyId_edges_all_but_debris when off); segmentation debris is always excluded.

Release-aware type mapping

BANC v626 and v888 remain separate type/bodyId namespaces. Their curated columns provide direct evidence: malecns_cell_type for MCNS, fafb_cell_type for FAFB, hemibrain_cell_type for hemibrain, and manc_cell_type for MANC. MCNS flywireType maps to FAFB only; it is not a BANC bridge. The two BANC releases additionally use the metadata-backed root_626 ↔ root_888 relation as the narrow banc_release_crosswalk bridge.

fafb_alignment_cell_type is a second, weaker FAFB lane (96.5% vs 99.2% fafb_match agreement). It is fallback-only: it fills a mapping just where fafb_cell_type produced no winner — 18 types per release, all cross-name — and its mappings carry the tier direct alignment label and are disclosed in the [BANC alignment fallback] run-note block. A curated winner or curated conflict is never touched.

The preview's summary strip reads in three tiers (2026-09-27): Mapped neurons is the CLAIM set (adopted pairs only, pure basis), Evidence reach (all flows) adds the disclosure ends the decision declined (hover the pair table's "not adopted" rows for the per-type decline reasons), and Out-map stays claim-scope. claim ≤ reach always; the validation report's headlines grade the claim tier and carry the disclosure as advisory material.

For a shared type queried in male-cns:v0.9, the mapping report shows v0.9 type → release_alias → v1.0 before any downstream cross-dataset linker. v0.9-only names use only their native *Type fallback and never borrow v1.0 body IDs.

Derivation guards keep the bridges honest: a curated BANC label hop (fafb_cell_type et al.) ends the derivation once it lands in the target namespace when the cell token names the target type exactly — a rename-resolved token terminates at the raw-token name node and the chain continues through FAFB's own additional_type(s) edge (2026-09-27 token chaining: fct 'SMP537' → aT → DN1pD), so the rename is shown rather than hidden in one hop; when a curated chain bridges the same token to the same target as a one-linker annotation chain, the annotation chain is dropped as redundant (curated subsumption). A primary's annotation cell naming another primary of the same namespace is a cross-reference, not a rename, and is never hopped through; and a derivation whose target-side evidence pools zero rows on the reached type is dropped rather than rendered with a 0 of n coverage.

Query-anchored merge granularity

Auto-mapping comparison runs build a per-run merge policy from your query chips, so the report is keyed by the chips' group labels instead of always folding names toward the male-cns namespace. The anchor is chosen from where your chips resolve: when all chips resolve into a common naming, the run anchors on the first chip's home dataset; chips that are the same native name in every selected dataset simply use that name (with the canonical fallback for everything else); mixed chips emit a [type granularity] note in user_warning_notes.txt and keep the minimal inseparable leaf rows, with a shared 1-to-N parent left as its own whole row. A clean reverse rename (e.g. FAFB 5th-LNv renaming into MCNS 5thsLNv_LNd6) never absorbs the split parent into a leaf row.

For a conflicted type such as MCNS 5thsLNv_LNd6 (which bridges two FAFB types): querying it from MCNS merges all its branches — FAFB 5th-LNv and LNd_CRY+_ITP+ with the BANC names that follow each — into one row whose target cells color the dataset-specific names (split-branch members share one color across columns) and collapse beyond three names. Querying one of the FAFB leaves instead yields that leaf's own row (with its BANC counterpart), while the MCNS parent stays a separate whole row. A type claimed by two queried parents (a fan-in leaf) merges with neither: it stays its own row, it is pruned from both parents' displayed rows, and a [merge fan-in] note explains why — and when the shared branch belongs to a queried parent, the note explicitly states that the parent's row is partial by design (the co-queried branch is presented separately at its own minimal level). The same prune also applies globally: a split branch that the type-mapper crosswalk itself lists as a 1-to-N target of a different parent type in the home namespace (even one not queried in this run) is contested — it leaves the queried parent's row and the merge counts, and a [merge fan-in] … global contest note names the rival parent. The custom label mapper overrides any of this when you know better.

Evidence surfaces for the split groups: the report's Type Mapping section leads with the role tables below and keeps the full canonical mapping grid as a collapsed appendix. The grid's Source (priority) column shows the one observation from the highest-priority dataset where the row resolves (male-cns → FAFB → other neuprint → BANC — a global dataset order, never the per-name merge anchor); a type that resolves in a single dataset keeps that dataset, and the remaining observations collapse into a tooltip. The source dataset's own target cell repeats its member name with a muted ● mark. The section also carries a collapsed Resolution topology card (per-group tree with per-branch bridge pool sizes and vote provenance), the run folder gains type_resolution_topology.json, and auto_type_mapping.csv gains additive anchor_group / auto_only columns. Mappings resting on auto-transferred labels only carry a ⚠️ auto-only badge on the auto-label source dataset cell of the grid (the BANC column in a BANC-anchored run) and are listed under a [BANC auto labels] note — they remain valid; the custom label mapper is the removal path.

Same-name-first within a fan-out. When a fan-out's candidate set contains the source type's own name (exactly — never as a prefix), the mapper selects that same-name candidate and demotes the other candidates to suspects. Rows carrying suspects show a ⚠️ suspects (N) badge plus a collapsed details block listing each rival (own 1-to-1 pair · votes · reverse target · rival pair status), and the section opens with a Same-name-first suspects card counting the fan-outs by disposition. The full per-rival evidence — whether the rival's own name also pairs 1-to-1 in this direction (own_1to1_pair / no_own_1to1_pair — an observation, not a verdict) and whether its mapping points back at the source — with votes, populations and a ready-made custom label-mapper entry, is exported to auto_type_mapping_suspects.csv. Suspects are never merged automatically; if you believe a rival is a buried fact, add the mapping with the custom label mapper. A terminal BANC vote conflict only selects when every rival is a confirmed duplicate; evidence_only (N-to-1 convergence) fan-outs are left as-is.

In the interactive panel and the viewer. The Type Mapping panel marks a same-name-first selection with a ⚠ suspects (N) badge in the row's own Suspects column — on the pair-card mapped pairs table, the forward/backward Type coverage tables, and the per-type breakdown. Hovering the badge explains the flag and lists the rivals (own 1-to-1 pair, votes, reverse target, rival pair status); the collapsed Suspects expander below each table carries the same facts, so the hover is additive and never the only route to the evidence (one row per rival: own 1-to-1 pair, votes, reverse target, rival pair status). A pair kept unmapped for the same reason says so in the Orphan list instead of looking unmapped for no reason. The "See available neurons" viewer with cross-dataset type mapping enabled shows the same three-way distinction in its annotations — curated relation, same-name-first selection, or the bare-name caveat — with the rivals behind a collapsed expander. Both surfaces display the mapper's facts; neither gates or merges anything. In the viewer's type list, the header checkbox is a tri-state select-all: empty selects every listed subtype, a partial selection also resolves to select-all (a partial page cannot know the unshown rows), and a checked state deselects the rows matching the current query. The full-table header checkbox behaves the same way over the whole result table.

Multi-value type cells. Some releases annotate a neuron with several candidate names in ONE type cell (e.g. DNp51,DNpe019). The cell stays a single atomic type name — no mapping changes — but rows carrying one are marked 🧩 multi, the run notes it as a data-quality item, and the conflicts CSV carries multivalue_source/source_parts.

The section's tables are organized by query role: Queried Sources (one row per queried source type, resolved per dataset with status colors), Queried Targets (same for target types), and Path Intermediates (distinct types that appear inside multi-hop paths, ranked by traversal count, showing the resolved name in each dataset — muted when the type resolves there but was not traversed in this run's paths — plus their query roles). A color legend between the table title and its intro line shows the six resolution colors (green identity/mapped/ bridged, blue taxonomy, purple valid split, amber fallback/evidence, red conflict, grey unmapped) plus the muted and — marks, rendered from the same palette as the cells. The full canonical mapping grid remains as a collapsed appendix. With separate_hemispheres enabled the run header carries a Hemisphere-aware run badge explaining the _L/_R/_U type suffixes.

Report tables: every data table renders in a ~20-row scrollable viewport with sticky headers (very large presence matrices are capped at 1,000 rendered rows with a note — the full set is always in the CSV exports). Similarity-trend plots split the comparison axis into two columns — per-threshold (left) and per-density (right, levels descending so thresholds increase left-to-right) — with one metric row each (Jaccard, Edge Rank, Cosine, Spearman). A metric row with no plottable value in any query renders an explanatory note instead of bare axes — for Spearman the note names the rule that applied: the query-keyed grid uses the ≥10-shared-edge gate, while the Standard-mode panel stays ungated (≥3-shared floor) so tiny samples remain visible for manual judgement. Neuron-count charts and tables show only the types present in their own role (source chart = source-present types only, target chart = target-present only).

Pathfinding threshold & bottleneck provenance

Every pathfinding row records both the threshold the user requested and the threshold that actually describes the materialized output. These are not interchangeable:

ValueMeaning
requested_thresholdThe entered Min Synapse Count before any budget effect.
applied_thresholdThe canonical equivalent Min Synapse Count: for a complete run it is the requested value; after a StrongestFirst budget bite it is w2 + 1 (tau_canonical), the minimal threshold that reproduces the materialized path set.
applied_threshold_sourcerequested, strongest_first_budget, edge_budget, or strongest_first_budget+edge_budget.
tau / strongest_first_tauThe StrongestFirst landing/collapse bound: the weakest retained path bottleneck at the path budget boundary. A complete run reports its natural weakest emitted-path bottleneck.
strongest_first_budgetThe effective path-output budget (0/empty uses the 1,000,000 auto default); strongest_first_budget_bitten says whether it was reached.
w0 / edge_weight_floorThe lossy Edge Budget floor applied to the graph in all mode. It is a threshold raise before path enumeration.
w1 / edge_budget_landingThe strongest edge-weight tier whose admission would exceed the Edge Budget; the floor lands just above it.
w2 / strongest_dropped_bottleneckThe strongest path bottleneck excluded by the StrongestFirst budget. The gap [w2 + 1, tau] is equivalent, so w2 + 1 is canonical.
W* / strongest_retained_bottleneckThe widest-path ceiling after lossless pruning; lossless pruning does not change it.
paths_completeWhether all intact paths within the search/depth bound were emitted; false means a budget affected the materialized set.

The same block is exported in each materialized data folder under dataset_data/.../ — a genuine requested run keeps the bare minsyn_{requested}, the collapse floor others alias to is minsyn_{applied}_applied_floor, and an aliased requested level is a marker folder minsyn_{requested}_skipped/ (README only, no data; a requested level coinciding with its own floor is skipped silently). Each folder carries parameters.txt, all_attributes.json, and data_details/parameters.csv; each dataset also writes APPLIED_THRESHOLDS.md. The comparison root also writes effective_thresholds.json for the UI notice and one row per dataset/threshold in comparison_results/pathfinding_provenance.csv. Combination mode additionally writes comparison_results/threshold_combinations.csv, one row per query_id and dataset, so the requested threshold map and the dataset-specific applied threshold are never confused.

Similarity score formulas

The cross-dataset comparison writes one row per dataset pair and per threshold into similarity_matrices/similarity_threshold_{N}.csv in Standard mode, or similarity_matrices/similarity_query_{query_id}.csv (where the filename uses a filesystem-safe query-ID slug) and similarity_by_query.csv in Custom combination mode. The manifest and table columns retain the original query ID. Let E1, E2 be the thresholded edge sets (edges with weight ≥ N) and W1, W2 the corresponding edge-weight vectors over the union of edges (missing edges = 0).

ScoreFormulaRange
jaccard_similarity|E1 ∩ E2| / |E1 ∪ E2|0–1
ruzicka_similarityΣ min(W1, W2) / Σ max(W1, W2) (weighted Jaccard)0–1
pearson_correlationPearson correlation of matched edge weights−1 to 1
cosine_similarity(W1·W2) / (‖W1‖·‖W2‖) over the union0–1
edge_rank_correlationSpearman ρ of edge-weight ranks over the union (missing = 0)−1 to 1
spearman_rank_correlationSpearman ρ of the compared values−1 to 1
path_rank_correlationSpearman ρ of path-probability ranks−1 to 1
rv_coefficient⟨E1, E2⟩_F² / (‖E1‖_F²·‖E2‖_F²) on normalized matrices0–1

Rank-based metrics return NaN with fewer than 3 non-zero edges; cosine returns NaN when both vectors are zero. These values are preserved as NaN in the CSV and rendered as 0 in the heatmaps. Weights are normalized before the RV coefficient so the metric is invariant to different total synapse counts.

Advanced options

  • Custom Mapping: the label-mapper panel button beside the dataset selectors — define inline groups or load them from history (see the label-mapper guide). With a mapping applied, group labels are compulsory: the shared label is what aligns datasets, so a blank row blocks the run at validation.
  • Skip BodyId Level: type-level only (faster, recommended).
  • Cache Only (Offline): no server contact; requires caches.
  • Auto Type Mapping: map equivalent type names across datasets.
  • Parallel Processing / Max Workers: tune speed vs API load.
  • Drop Untyped Neurons: removes edges touching untyped neurons (empty / Unknown / NaN / all-digit bodyId-fallback labels) using the SAME shared predicate as the pathfinding tabs (utils.label_utils.is_untyped_type_label), applied AFTER the standardized cross-dataset labels are resolved (post label-mapping). Comparison-level records land in comparison_results/untyped_dropped_records.csv, while each delegated per-dataset pathfinding folder intentionally keeps raw rows; counts are appended to user_warning_notes.txt.
  • Hemisphere analysis (its own card): Hemisphere-aware (off) separates L/R labels; Symmetry Analysis (on) is auto-enabled with Hemisphere-aware and forced off otherwise; Keep Only Hemisphere-Conserved Edges requires Hemisphere-aware. Find Reciprocal Connections is a separate Core Parameters checkbox for reciprocal graphs. The threshold chips control is labeled Synapse Thresholds; under the Connection-ratio basis a twin editor (Connection-Ratio Thresholds, float tiers in (0, 1], default 0.001 / 0.005) takes its place — the Threshold Basis selection swaps which editor shows.

The Type Mapping panel

The Type Mapping button (enabled when ≥ 2 selected datasets have cached neuron indexes) previews the auto type mapping the run will use — informational only, please double check. The same validity-aware decision (shared resolver, comparison/type_resolver.py) backs the panel, the viewer's See available neurons mapping, homolog finding, and the connectivity-profile comparison. A Route scope selector above the preview picks the mapping's route universe (re-ratified 2026-10-01): Curated (default) is exactly the historical licensed routes, while Full map is a complete parallel mode — all datasets are licensed as connectors (the previously disabled BANC routes included: HEMI↔FAFB ends via BANC bridges, FAFB↔BANC via male-cns, …). In full mode the whole panel runs on that universe: flows, the claim/reach readout, the summary strip's labeled Full-map ends cell, the per-type breakdown's Full-map reach column (delta, via <mid> badges, ∧ route-conflict markers), the bridge visualizations, and a per-pair Export full-map routes (CSV) — all matched to the same composed routes. The validation pipeline accepts the scope gated (RunMappingValidation.py --route-scope full); composed pairs are labeled route_basis/via_mid in its exports. Per-hop licensing rules are unchanged in both modes — full map widens the route universe, never the per-hop rule set.

  • Unique rename (e.g. MCNS MeVPLo2 ↔ FAFB MTe07): one canonical target everywhere.
  • Valid split (e.g. MCNS VS → FAFB VS1…VS8): every licensed branch is listed; no arbitrary single target is chosen. For a queried split parent the panel additionally resolves the split per neuron (see bodyId-level split resolution below).
  • Conflict (e.g. BANC CB1011): fails closed — no automatic target, and the type is never merged by raw same-name in path/edge tables or comparison anchors.
  • Unmapped: keeps its raw name as the counted long-tail fallback (surfaced in the saved metadata's raw_fallback_used).
  • Search: one query per chip (exact / starts with / contains / ends with / regex), with dataset-aware type suggestions. A chip that names a taxonomy value (e.g. FAFB cell_type circadian_clock) expands to that label's member types. The exported Mapping graph (HTML) and Mapping sankey (HTML) plot types only — the chip itself is search provenance, so it appears in the tables and CSVs, never as a node on the canvas. The per-pair Network (type-level) download follows the same rule, and still presents the dataset where the query resolved on the left.
  • Centre-source layout: when one dataset is the origin and exactly two receive it, both exports place the origin in the middle column with one target on each flank (target 1 | origin | target 2), the denser flank on the left. The composed Sankey covers one or two target datasets; for a wider selection use a pair card's Sankey (type-level). Sankey ribbons are labelled in neurons — the mapping views never say "synapses".
  • Summary table (per dataset): Matched types, Neurons (the issued side — every matched type is issued into the resolution, flowed or orphaned), Mapped neurons — what the dataset RECEIVES: the branch-claimed bodyIds (union of the branches' resolved pools, each bodyId counted ONCE — the claim set per plan-same-name-fidelity-and-three-level-coverage.md; the received types' full populations are the reference denominator), shown as {N}({m} types) from 2 distinct received types up, plain {N} otherwise — a dataset that only issues the query reads 0 — plus Out-map (in-map types), the received types' own neurons that the claim set does not reach (union of those types' populations minus the claim, so a type pooled on its full population contributes 0; on circadian_clock → male-cns this reads 219 − 204 = 15, while the validate-expand-visualize run's family bin holds 11 rows because a morph-qualified candidate closes holes there and nothing does in the panel), plus Unmapped (orphans stay visible).
  • Pair cards (src → tgt · N mapped pairs): Type, Mapped to, Neurons (source → foreign), Relationship (the per-flow cardinality, matching the coverage tables and the CSV), Suspects (a ⚠ suspects (N) badge on a row whose same-name-first selection demoted rival candidates — hover the badge for the explanation and one line per rival, or expand the collapsed Suspects block below the table, which carries the same facts as a table), Map used (the derivation linkers, e.g. flywireType 'LMTe01' + additional_type(s) 'LMTe01'), and Pool coverage — one basis-aware cell per side so the states can never be confused: a measured subset (FB: 1,655 of 1,683 (98.3%)), an unconstrained full population (FB: all 1,683 — the chain names the type identity, nothing was filtered), an unmeasurable side (FB: not measured — the coverage index is unavailable), and a missing pool (not pooled). A measured zero renders explicitly as 0 of n (0.0%). Coverage is measured independently per endpoint; the mapper does not infer bodyId-to-bodyId pairings. When more than one supported bridge chain reaches the same endpoint pair, the card identifies the selected bridge and the all-valid union; the latter includes the unique bodyIds from supported alternatives. Raw linker values such as auto:MeVPLo2 and their canonical matching tokens are retained in the extended export. The card's Out-map (this type) column is the endpoint type's own neurons this branch's pool does not reach — per branch, so split branches can each quote the same neuron; it reads not adopted on a disclosure row and not pooled where no pool resolved.
  • Type coverage tables (top-level expansion per pair, bidirectional): the FORWARD view lists each queried type with its neurons, mapped targets, 1-to-N/1-to-1, a Suspects badge column, and per-side coverage; the BACKWARD view lists each receiving type with the sources that map onto it, read from the receiving type back to its sources — relationship cells follow the row subject's fan-out, so a row with several sources reads 1-to-N, never 1-to-1. Backward rows marked dataset-wide incoming list EVERY source type in the source dataset that maps onto the receiving type (the active query marked in Mapped from) — the context that explains why one queried type's few neurons fan out to a large target population (e.g. MCNS SMP227: 6 neurons → 94 FAFB neurons, whose receiving types collect from 4/4/6 incoming MCNS types). This context is explanatory evidence, not a canonical acceptance of every incoming source. Coverage columns carry short labels such as MCNS · selected; hover a header for the full dataset key and the scope explanation — selected = the first supported bridge chain after deterministic evidence ordering (the primary chain behind edge weights and hovers, not a biological adjudication), all valid = the deduplicated union of bodyIds from every independently supported candidate bridge (completeness of supported evidence; branches are not mutually exclusive). In a dataset-wide row the source denominator is the union population of ALL incoming source types. Split branch rows are labeled as branch evidence (non-exclusive); overlap counts explain when the same source bodyId supports multiple branches. Cells read x of y (share) with thousands separators; a side whose coverage index is unavailable renders not measured (never a fake zero), and a row without any pool renders not pooled. The state legend rides on the expansion title's hover. That title is data-driven — it reads 1-to-N fan-out / N-to-1 fan-in / all 1-to-1 off the forward rows and appends · ⚠ N suspect pair(s) when the pair carries suspects, so the heading always matches the tables. The per-rival suspect details render once, in a collapsed Suspects block below the tables.
  • Same-name pairs: a pair sharing its name derives through its metadata bridge when one exists (e.g. flywireType 'DN1a' — the male-cns crosswalk cell verifies it); the bare "same name — no metadata verification" warning appears only when no evidence connects the pair.
  • Exports: Sankey (type-level / linker), Network (type-level / linker paths), the Mapping graph (HTML, downloaded as mapping_graph_*.html), the cross-dataset Mapping sankey (HTML, mapping_sankey_*.html; one column per dataset with the origin centred, offered whenever the selection is one origin into at most two targets), and Export mapping (per pair and all pairs (CSV); filenames mapping_*.csv). One fixed column set: source_dataset, source_entry, matched_column, source_type, target_dataset, target_type, relationship, source_neurons, target_neurons, bridge, bridge_columns, mapping_origin, numeric source_pool/source_total/ target_pool/target_total, the FULL per-type bodyId populations (source_body_ids / target_body_ids — every bodyId of the mapped type in its own dataset, one brace-wrapped comma-separated list quoted as one CSV field per cell so spreadsheet delimiters never split it; listed per type, never paired across datasets), plus the human-readable pool_coverage and pool_coverage_basis columns. The UI's extended export additionally carries the selected bridge, mapping status, selected rank, valid-chain count, raw/canonical selected linker values, unsupported attempts, selected/all-valid pool IDs and totals, overlap, and scope, plus target_out_map / target_out_map_body_ids — the endpoint type's own neurons this branch's pool does not reach (a set difference, so a full-population basis reads 0 and an unresolved pool stays an empty cell rather than a false 0; this is the panel-side overhang, at least as large as the validation run's family bin because no morphology closes a hole here). The full mapping is never silently dropped — a +N more flows notice points at the CSV when the drawn cap trims).
  • BodyId-level granularity (row-based bridge evidence): the mapper's granularity mechanism is the bridges' own row-based evidence — each branch's linker-refined bodyId pool (the linker rows tie specific bodyIds) and per-bridge label-vote provenance (curated vs auto:, e.g. the BANC aMe24 bridge: 1 auto vote vs s-LNv_a: 2). These pools and votes are what the split rows, coverage cells and exports carry — no connectivity similarity is involved anywhere in the mapper. When several types are queried, or a chip resolves to many types (a taxonomy label such as circadian_clock), a collapsed Per-type breakdown expansion shows one row per (matched type × target dataset) — the mapped counts are specific to the row's target dataset, never summed across datasets — with the originating query chip and the combined {N}({m} types) Mapped-neurons cell.
  • Legends: the artifact header carries one chip per entry in the CODE: full name (count) format — datasets (with node counts) and the bridge linker columns (color-coded: flywireType male-cns→FAFB crosswalk, additional_type(s) FAFB cells, curated BANC label columns, Alternative Cell Type(s) BANC cells, banc_release_crosswalk, and hemibrainType/mancType crosswalks). The linker network lays out ONE column per linker (e.g. MCNS type → flywireType → additional_type(s) → FAFB type = four columns). On the FAFB↔BANC pair (both directions), annotation routes through Alternative Cell Type(s) or additional_type(s) never extend past a same-name arrival — such transitive extensions are only offered when the pair is confirmed by a reverse-direction bridge, and then carry a (reciprocal) provenance in the exports.

Validating a mapping — the TM VEV pipeline (CLI)

The panel preview is informational. To grade a mapping at bodyId level — and estimate how much of the gap its evidence can fill — run the validation pipeline (type-mapping validate-expand-visualize, TM VEV) from the repo root:

python3 scripts/RunMappingValidation.py     --source flywire_FAFB_v783 --target male-cns:v1.0     --types circadian_clock --mode family     --scene-selfcheck --output-dir /path/to/data
  • Confidence tiers: matched (asserted) > verified > borderline > unmatched for in-pool targets; sibling, candidates, family, relative, examinees for the expansion (nested modes: restrictive / family / aggressive; examinees was renamed from suspicious — the type mapper's rival-suspects concept owns that word now).
  • Same-name-first: when the type mapper selects a fan-out candidate carrying the source's own name, the pair is marked ⯼ in the report and the withheld rivals can be verified connectivity-wise with --verify-suspects (advisory; held/excluded fan-outs land in same_name_excluded.csv).
  • Layered gap-fill report (gap_fill_levels.csv): every non-claim bodyId graded high (native floor) / medium (Track-A backup B_b − Δ) / low (null bar) / type_gated (family) / advice (relative); hole-closing candidates annotated.
  • Out-map branch per type: the unclaimed source neurons (no branch pool claims) beside their expansion candidates (connectivity-ranked, morph-checked) — the source-side gap next to the fill.
  • Scene notes: root groups start expanded one layer; sibling layers start hidden (one eye click restores); the run root folder carries the type-map-validation_ prefix and sorts its exports into validation/, expansion/, gap_fill/ and mapping/ (folders written before that change keep every CSV at the root).
  • Machine-readable progress lands in pipeline_progress.jsonl; full export contract in docs/OUTPUT_FILES.md §9.

Thresholds are nested — and the run states its real cutoffs

Each threshold run discovers its own cone (edges ≥ threshold), so result sets are nested: paths kept at t=10 also exist at t=5 and t=3. Runs are bounded by StrongestFirst's Max Paths budget and the lossy Edge Budget floor; a clamped run at threshold t is exactly a complete run at its reported applied_threshold. The landing tau is the StrongestFirst collapse bound, not necessarily the minimal equivalent threshold: when a budget bite leaves a gap, w2 + 1 is the canonical applied threshold. The Edge Budget acts first on the graph at w0 (with landing tier w1), and the path budget then acts on output paths; W* records the strongest retained path bottleneck. Shortest mode can be tau-bounded by Max Paths but is never Edge-Budget-floored. The same explanation and values appear in effective_thresholds.json and pathfinding_provenance.csv; collapsed rows additionally carry skipped/duplicate_of markers.
