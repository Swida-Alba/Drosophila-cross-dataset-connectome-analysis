Input File Formats

Every upload menu accepts the formats below. The same rules apply to entries typed into the chip input; use a file when loading a larger list.

Neuron lists (CSV / TSV / Excel)

Used by Find Path, Direct Connections, Connectivity → Comparison and Cross-Dataset panels.

FormatRuleExample
CSV / TSVOne neuron per row. The first column is read. aMe12
aMe10
PPL101
XLSX / XLSThe first sheet, first column is read. Column A: aMe12, aMe10, 720575940610453042

Optional header names are skipped automatically (case-insensitive): type, neuron, name, bodyId, id, body_id.

Each first-column row becomes one neuron entry. The chip input accepts one query at a time; use this file format for a list.

Path files (Find All Paths output)

Used by the Path Network (PlotPath) panel. Upload one of:

  • *_allpaths_type.csv - type-level paths (recommended)
  • *_allpaths_bodyId.csv - bodyId-level paths
  • *_allpaths_info.xlsx - Excel workbook with path sheets

The file must contain either a path column (path_block or path) plus weights, or an edge list (source/target/weight or *_pre/*_post/weight). The full specification - all accepted column names, edge lists and connection matrices - is in the Network guide.

Neuron layers (3D skeleton)

The Skeleton tab arranges neurons into display layers with the built-in layer tree editor — no CSV upload needed. Drag layer rows to reorder them and drag neuron chips between layers; each layer accepts types, instances, bodyIds or regex patterns, and an optional custom name. The editor serializes to the same nested-list format the script-level layer_map_csv parser produces, so a scene built in the UI is identical to one built from a mapping file. See the 3D Skeleton guide.

Common mistakes - Saving CSV with BOM/UTF-16 - use UTF-8. - Putting neurons in the second column - only the first column is read. - Uploading a path file with only path and no weights column.
