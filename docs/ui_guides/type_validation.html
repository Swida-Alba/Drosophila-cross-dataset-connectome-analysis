Type Validation (TM VEV)

BodyId-level validation of a source → target type mapping between two connectomes (e.g. flywire_FAFB_v783 vs male-cns:v1.0). It verifies the mapper’s claimed branches against real connectivity, expands candidate neurons, and renders 3D review scenes. Everything it produces is a proposal - the mapping itself is never rewritten.

Where it fits

This is the validation counterpart to the Paths tab. Paths compares connectivity across datasets; Type Validation checks whether a proposed type mapping between a source and a target dataset actually holds at the neuron level. Read the type-level preview, then validate at bodyId resolution.

Quick start

  1. Pick a Source Dataset and a Target Dataset. They must differ; same-dataset pairs usually resolve no cross-dataset branches.
  2. Add one or more Source Types / Categories as chips: a neuron type (APDN3, s-CPDN3A) or a coarse cell_type category (circadian_clock). A query is required - an empty query runs but produces an empty report.
  3. Choose a Validation Mode: restrictive ⊆ family ⊆ aggressive. Wider modes admit more candidate bins and run slower. The fourth button, pooling, is not a wider rung: it is a parallel unsupervised search that scans the queried population against the whole target universe under absolute floors, writes its result into pooling/ beside the nested bins, and changes none of them. Selecting it reveals its own gate card (Jaccard floor, the rank window, morphology as the last gate, the morph budget); the other modes never read those knobs. The floors are a volume guard-rail — the configured number is what gates the scan, and nothing fits it to this dataset pair’s evidence — while the morphology control is a true gate: a candidate scored below its bar leaves the exported pool and the scene root.
  4. Toggle Stages as needed (morphology, 3D scenes, backward reciprocal evidence, out-map expansion) and set the offline behaviour in Data & Offline.
  5. Click Run Validation. When it completes, open report.html, the run folder, or the latest 3D scene from the action row.

Cost & scope

Validation scans each source neuron against the full target universe (140–180k neurons). A coarse category, aggressive mode, or backward reciprocal evidence each multiply runtime - a single backward reverse scan is roughly 4–7 s with a budget in the hundreds of neurons. Start with a type-level restrictive pass. 3D scenes default to Max scenes = 0, which renders one page per parent type - a coarse category therefore pays for every scene it resolves. Set a positive cap (the run names the parents it drops) or split a broad query into separate runs.

Offline runs

Use connection cache is not an offline switch - turning it off only forces a refetch. To stay offline, check Cache-only profiles (skip online profile build), and also turn Morphology verification and Render 3D review scenes off (stage-2 profiles, morph vectors and skeleton loads are what reach the network). An unsupported dataset pair is not an error - it resolves to zero branches and an empty run, so check the log for “no type pairs resolved”.

Backward (reciprocal) evidence

With Backward (reciprocal) homolog evidence on, stage 5d asks the same homolog question from the other side: each candidates / family / relative member - and, by default, each unmatched pool member - is reverse-scanned against the whole source universe. Already-mapped members (matched / verified / borderline) are skipped, because their forward pair already is the symmetric evidence; that is why the only pool-side toggle is Backward scans unmatched pool members. Each scanned neuron gets an advisory high / medium / low grade for how prominently its own branch’s source type ranks in that reverse scan — in either ranking, so the grade is pure rank evidence with no score threshold. It never moves a neuron between bins and never counts toward a fill. Read it in the report’s Reciprocal tab (one row per neuron, ordered by the Jaccard of the branch-type hit the grade rests on, so a neuron with no such hit sinks below the ones that have one; it is shown beside the global top-1) or in expansion/backward_matches.csv.

Output

The run lands in <output>/type-map-validation_{SRC}_to_{TGT}_{timestamp}/ with validation/, expansion/, gap_fill/, mapping/ CSV/JSON deliverables, a report.html, and visualization/plot-3d_*/ scene folders. The pair_summary.csv and gap_fill_dedup.csv are previewable in the Output Files panel.
